`index list` reads tracked paths, `status` reports staged and unstaged changes (`--untracked` also
lists untracked files), and `ignore check` explains ignore rules. `checkout` replaces the index and
working tree without moving HEAD. `worktree list`, `lock`, `unlock`, `prune` and `repair` manage
linked-worktree registrations. Run `girt help checkout` and `girt help worktree` before changing
state.

:::caution[Experimental CLI]
The girt CLI is not a replacement for Git. It exercises the library's Git operations and provides a
testing surface for performance and byte-for-byte comparisons with Git. Command names and parameters
may change; the library is the core deliverable.
:::

## List tracked paths

<CommandExample
  command="girt status --untracked"
  api="Repository::status"
  apiPath="repository/struct.Repository.html#method.status"
  git="git status --porcelain --untracked-files=all"
  note="Default girt status omits untracked files; add --untracked to include them."
>

Use the repository from [Getting started with the CLI](/girt/cli/getting-started/).

```text
$ girt index list
notes.txt
```

The index records `notes.txt` as a tracked path. `status` compares HEAD, the index and working tree;
its two status letters describe staged and unstaged changes. Add `--untracked` to include files
outside the index. For example, after creating an untracked `draft.txt`:

```text
$ girt status --untracked
?? draft.txt
```

`??` marks an untracked path. `ignore check <path>` explains whether an ignore rule matches and
prints its source and pattern when one does. `worktree list` prints each checkout's path, HEAD ID
and branch or state. `checkout <tree>` replaces files and the index without moving HEAD or switching
branches; use a disposable copy for checkout experiments.

The corresponding Git operations are `git ls-files`, `git status --porcelain --untracked-files=all`,
`git check-ignore -v`, `git worktree list` and `git read-tree -um <tree>`. girt's default status
omits untracked files, like `git status --porcelain -uno`; its flags and record formatting follow
its own CLI conventions.

</CommandExample>

## Library API and limits

Index listing reads [index::Index](https://docs.rs/girt/latest/girt/index/struct.Index.html). Status
and ignore use [Repository](https://docs.rs/girt/latest/girt/repository/struct.Repository.html)
methods `ignore_rules` and `status`; checkout calls `checkout_tree_with_progress`. Registration
commands use `worktrees`, `lock_worktree`, `unlock_worktree`, `prune_worktree` and `repair_worktree`
on that same type.

Status and checkout compare raw bytes on macOS/Linux, without filters, EOL conversion or
`core.filemode`; macOS paths must be ASCII. Checkout drops derived fsmonitor and untracked caches,
and refuses split/sparse indexes, resolve-undo data and unknown extensions. Prune deletes a missing
checkout's registration, HEAD and index; inspect its help before use. See
[The index and working tree](/girt/guides/index-and-working-tree/) for safety and partial-failure
contracts.
