This benchmark runs the same jj commands three ways: jj built on girt, stock jj (which uses gix and
the `git` executable), and the closest `git` command. It uses three real repositories: jj's own
history (small), git.git (medium) and Linux v6.1 (large). Everything on this page is generated at
build time from the committed results JSON. The underlying data, issue links and per-cell notes are
tracked on [girt issue 66](https://github.com/joshka/girt/issues/66) (performance gaps against Git).

## How to read the tables

Operations are grouped by how often a jj user typically runs them, because a delay that is fine for
`jj git clone` is painful for `jj status`. Each group has its own four time bands.

Each cell shows jj with girt's median time, coloured by band. Below it are stock jj's time, the
ratio (girt ÷ stock, lower is better) and Git's time. Cells outside the fastest band carry tags
saying who is responsible:

- **girt:** jj with girt is at least 20% slower than stock jj.
- **jj:** stock jj is also outside the fastest band, so jj's own work is part of the cost.
- **near bound:** stock jj sits just inside a band boundary and girt is less than 20% slower.

Linked numbers are the girt issues tracking that cell. "Refused" means girt stopped with an explicit
error, usually a resource limit, instead of producing a result. "Timed out" means girt exceeded
twice stock jj's time (at least 5 seconds).

## Method

Each tool runs against a fresh copy of the same fixture. Caches are warm and machine load was not
controlled, so treat small differences as noise. Times are medians of the samples listed in the
JSON. Most cells take six samples per tool. Cells whose first sample takes more than 10 seconds take
three, and more than 60 seconds take one, so their ratios are less precise. Some Git equivalents do
different work: Git has no counterpart to `jj undo`, `jj op restore` or colocated initialization, so
those cells have no Git time. Each row's workload note in the tables describes what was measured.

The harness is `scripts/jj-e2e/bench-ops.py` in the girt repository. Results and provenance live in
`docs/jj-performance.json` and `docs/jj-performance-provenance.json`. This page re-renders from
those files on every build.
