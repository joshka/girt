# R24 Configured SSH Evidence

R24 connects an R21 SSH destination to the existing OpenSSH fetch/push adapter. The application
selects an executable, OpenSSH config and default user. When `GIT_SSH_COMMAND`, `GIT_SSH` or
`core.sshCommand` is selected, the value must exactly match an application-approved executable and
literal argument vector. Girt never interprets a configured shell snippet. The `ssh` command variant
is supported; another variant fails before process creation.

## Acceptance Boundary

- Supported destinations are `ssh://[user@]host[:port]/path` and `[user@]host:path`, with the
  component and length limits of `SshRemote::new`. Percent encoding, URL query/fragment fields,
  implicit tilde expansion, arbitrary command variants and Windows process execution are refused.
- The application may supply an agent socket or askpass executable for an encrypted key. Girt clears
  inherited environment, passes only selected PATH and authentication variables, and keeps strict
  host-key checking, no password or keyboard-interactive authentication, no host-key updates and the
  existing no-forwarding/no-proxy process policy. OpenSSH config, approved arguments and askpass
  executables remain trusted application policy.
- The configured path uses the existing owned SSH `Session`. Cancellation, deadlines, child group
  cleanup and `NotSent` versus `Uncertain` push classification have the same behavior as explicit
  `SshRemote::new`. No automatic retry occurs. Authentication, command, key and endpoint bytes are
  excluded from Debug and errors.

## Local Evidence

Original disposable fixtures in `tests/fixtures/ssh/server.py` create throwaway server and client
keys, including an encrypted identity. A temporary shell askpass program supplies a synthetic
passphrase. A disposable `ssh-agent` loads a temporary key through an application-selected socket.
The real Git upload-pack test fetches through the configured URL with each authentication route. SSH
transport units cover command precedence, exact approval, variant and endpoint refusal, literal
argument construction, agent/askpass environment, and redaction. The existing SSH suite covers real
Git push, host-key refusal, cancellation, uncertain post-send outcomes, exit and process group
cleanup through the same `Session`. No production credential, key or server is used.

Local validation on macOS arm64: Git 2.55.0, OpenSSH 10.3p1, Python 3.14.7 and Rust 1.98.1.
`cargo test --features ssh --test ssh` passed 40 cases; the focused SSH units passed 21 cases.
`just check` passed all-feature unit, integration and doc tests, formatting, all-target Clippy and
docs.rs at `fb261a5f`. A later command-construction refinement removes a process-global PATH read
from configured connections; all 21 focused units, the configured real Git fetch and all-target
Clippy passed afterward. A test-only change also suppressed `ssh-add` fixture diagnostics; its
focused agent case and formatting checks passed. Markdown lint passed on the changed narrative files
with the maintainer's 100-column config. No new dependency was added. The existing SSH benchmark
still measures the transfer path; R24 changes command selection and authentication setup rather than
its steady-state data path, so no new throughput benchmark is warranted.

## Remaining Limits and Restart Criteria

Native Windows SSH remains unsupported. Reopen when a required Windows consumer endpoint needs it;
test native argument quoting, console, descendant containment, cancellation and uncertain pushes.
The `simple`, `plink`, `putty` and custom variants remain refused. Reopen a variant when a required
endpoint or jj configuration selects it, with an approved argument contract and synthetic process
fixture. Percent-decoded paths and additional SSH URL forms need a concrete consumer case; retain
refusal until their byte and quoting behavior is specified. Agent forwarding, proxy/jump hosts,
password/keyboard-interactive authentication, protocol v2 and connection reuse remain outside the
scope. Local/file and helper transport belong to R25.
