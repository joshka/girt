# C03 Transport Coherence Review

## Scope and Decision

This review inspects the R21–R30 transport stack at R30 code revision
`fd6dd09158406a4a934b56e48f7f648f17fe76fe` and its evidence child
`68e2b7783e83ec4be7cd529b0df151a966252e10`. It uses the retained capability reports and selected
public boundaries and fault paths, not a new exhaustive audit of every implementation. The C03
review change clarifies the push module's credential contract. Native validation of that exact
change remains an A16 gate before checkpoint acceptance.

## Findings and Owners

1. **No established mutation-certainty blocker.** `push::send` counts successful wire bytes and
   marks only reached command packets as attempted. Zero successful request bytes return `NotSent`;
   a partial first packet is uncertain. SSH retains the session's written-byte count. HTTP treats an
   initiated mutating POST as uncertain even if a network error gives no proof of delivery.
   Completed status packets and progress survive interrupted response reads; absent status and an
   incomplete proc-receive rewrite do not prove rejection or a destination name. Native local push
   may install objects before reference publication and reports per-ref publication and log effects.
   These distinctions are sufficient for a caller to inspect remote state before retrying. They do
   not provide a transaction across commands or transports.
1. **Small API guidance drift, corrected here.** The `push` module still called credential discovery
   deferred after R22 introduced `remote::CredentialSession`. The revised module guide points
   callers to that separate, application-approved lifecycle. Remote configuration still chooses
   destinations and refspec mappings; the application resolves protocol policy, credential scope,
   transport trust and auth outcome. No new implicit environment or helper execution is introduced.
1. **Live progress remains an integration decision.** R30 returns bounded sideband progress in
   `PushReport`, including valid frames before response interruption. Owned HTTP and SSH exchanges
   do not call a live progress callback. R35 must inspect the actual jj UI/cancellation call sites.
   If an ordinary required push needs live progress, add a bounded callback or stream at the
   transport boundary before final replacement. Retained progress alone is not live delivery.
1. **Proc-receive evidence is narrow.** The R30 parser covers v2 options and incomplete rewrites;
   one original Git HTTP SHA-1 Unix fixture verifies an actual alternate ref. Synthetic packets
   cover malformed and partial responses. R35 must identify required Gerrit or other endpoints.
   Extend the original hook fixture to the applicable transport and SHA-256 format before claiming
   those server combinations, or retain an explicit unsupported boundary if jj does not require
   them. An incomplete rewrite requires remote inspection before updating a local view.
1. **Native receive exclusions remain explicit.** Hooks, proc-receive, `updateInstead`, push
   options, selected fsck/input-size policy and shallow destinations refuse before native local
   mutation. R35 owns comparison with jj's actual local-push destinations. Any required exclusion
   needs its own implementation and native validation before final replacement; no broad receive
   policy redesign is justified by the current inventory.
1. **Credential early exit is fixed; tracing remains open.** R26's two-helper fixture has a
   successful second helper that prints credentials without reading stdin. Depending on scheduling,
   its parent writer could receive `BrokenPipe` and abort a valid lookup. C03 ignores only that pipe
   closure after a successful child exit; nonzero exit still permits the next helper, and other I/O
   errors still fail. An original large-input test forces the successful early close. B04's
   zero-`fetch.http` capture recurred on macOS in R30 and can hide a tracing-lifetime regression.
   The failed assertion has no accompanying fetch failure or missing object evidence, so a tracing
   fixture or instrumentation cause remains plausible but unproven. B04's C03 follow-up must retain
   complete spans from a failed run and inspect dispatcher ownership when a download changes worker.
   The separate split-index oracle failure remains with C02. Green reruns do not resolve B04.

## Integration and Evidence Boundary

The public division is coherent for the planned jj integration: resolved configuration and
credentials belong to the application, transports own cancellable exchange and process cleanup,
fetch separates verified download from installation and conditional ref publication, and push
reports per-command evidence instead of retrying. Blocking caller-owned streams require caller
interruption; owned transports have explicit controls and runtime ownership. This review finds no
need to combine these layers or add a generic transport trait before R31. R35 retains the actual
consumer gate, including v2-only fetch servers, native local exclusions and live progress.

R30's [exact-revision native runs](r30.md#exact-revision) cover Ubuntu 22.04/24.04, macOS 14 and
Windows Server 2022, with SHA-1 and SHA-256 in applicable suites. They include reruns of unrelated
flaky jobs, recorded above. C03 changes credential process behavior and adds its focused regression
fixture. Its own local and exact-revision native results must be recorded before changing the
roadmap status to scoped accepted. The applicable proc-receive format/transport matrix and B04
investigation remain assigned work, not unqualified compatibility claims.
