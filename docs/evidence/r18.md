## Contract and Draft API

`Objects::detect_rewrites` composes structural tree comparison with stored-blob inference. The
public `rewrites` module exports `Options`, `Copies`, `Limits`, `Rewrite`, `Kind` and `Error`.
Private `detect` owns candidate collection, verified blob reads, exact pairing, edited pairing and
filtering; `similarity` owns bounded span accounting. No dependencies are added. Both hash formats
preserve raw path bytes. `examples/rewrites.rs` emits NUL-delimited records from an explicit
repository and pair of tree IDs.

Deleted regular/executable blobs supply rename candidates. `Copies::Modified` adds modified-file
preimages (including mode-only modifications) and source reuse; unchanged sources are excluded.
Destinations are added regular/executable files. Symlinks and gitlinks never become records.
Structural leaf comparison covers file/directory transitions. Empty sources are excluded by default;
callers can enable exact empty matches. A 100% requested threshold requires identical object IDs.
The default edited threshold is 50%, inclusive before score rounding. Results are deterministic and
sort by destination path. Target filters apply after inference and classification, so selection does
not change competing destinations' assignments.

The draft score splits bytes at LF or 64 significant bytes, matches equal spans with multiplicity,
and divides retained bytes by the larger raw payload size. Text ignores CR immediately before LF; a
NUL in the first 8000 bytes selects binary spans that preserve CR. Edited ties currently rank
rounded percentage, matching basename, source path and destination path. Exact matching prefers an
unused deleted source, matching basename and then source path. These independently chosen details
are **not** a claim of identical Git scores or pairing heuristics.

The operation never reads attributes, performs clean/smudge/textconv conversion, or accesses an
index or worktree. Callers own configuration, scheduling, merge and copy-history algorithms. The
unchanged jj call site specifies 50% similarity, a 1000 limit, modified-file copies, no empty
sources and post-inference target filtering. Those are concrete caller policies; its heuristic
choices are not automatically requirements for this Git library. Its CLI summaries omit some copy
relationships, so CLI absence alone cannot establish the underlying copy-record contract.

## Acceptance Cases and Outstanding Work

- Verify exact and edited text/binary content, scores at/below threshold and identity-only requests
  in both formats against independent Git operations.
- Exercise modified sources, mode changes, empty policy, symlink/gitlink exclusion, byte paths,
  file/directory transitions, deterministic ties and target filtering.
- Establish candidate-limit behavior after exact matching, aggregate payload/span/pair/work limits,
  cancellation, missing/corrupt/wrong-kind storage and no partial results or writes.
- Characterize attributes/filter configuration actually used by unchanged jj without treating
  enabled dependency features as requirements.
- Measure representative exact/edited inference and candidate explosion with Criterion; separate
  library work and fresh-process boundaries and retain matched Git output where applicable.
- Complete the independent scoring/pairing investigation below before claiming Git compatibility.
- Native coverage, broader fault/cancellation cases and final completion checks remain open until
  the algorithm's compatibility boundary is resolved. Existing unaffected checks can be reused.

Default bounds are 64 MiB of distinct retained blob bytes, one million span occurrences, one million
candidate pairs and 100 million conservative work units, plus the existing tree/read bounds. Edited
search rejects more than 1000 sources or remaining targets after exact matching. Exceeding a bound
returns structured failure and no partial inference; Git's CLI may instead emit an incomplete diff
with a warning. Cancellation is cooperative, checked around storage, per candidate and while
scanning/scoring. Individual reads, allocations and sorts are not interruptible. No partial
repository mutations or cleanup races arise because this operation is read-only. These bounds do not
promise an exact RSS limit or recoverable allocation failure.

## Independent Observations

Original fixtures use only public Git commands and unchanged installed jj 0.45.1. No Git, gix or
libgit2 implementation or test source was consulted. jj's own consumer call sites and tests were
inspected to identify requirements. The original generator
[`observe.py`](../../tests/fixtures/rewrites/observe.py) records Git 2.55.0 `diff-tree` and jj
`diff --summary` results, including exact tree/commit identities. Inputs are defined in the
generator.

Git's [diffcore documentation](https://git-scm.com/docs/gitdiffcore) establishes deleted and
modified copy sources, configurable similarity and basename preselection. The
[diff documentation](https://git-scm.com/docs/git-diff) establishes candidate limits, exact matching
and empty-source choices. Neither document specifies a complete score or pairing algorithm.

The initial corpus agrees for ordinary half-retained lines, growth/shrinkage around 50%, final
unterminated fragments and empty exclusion. Git and jj differ for reversed lines (Git R100, jj no
rename), CRLF-to-LF (Git R066, jj no rename), edited binary lines (Git R075, jj no rename), and 128
repeated `a` bytes changed to 64 `a` plus 64 `b` (Git R100, jj no rename). The draft span comparison
scores that last pair 50. Its cause is unresolved; the observation alone does not prove hash
collisions. Required failing filter/textconv commands in configuration do not run during the
original raw-tree observation with stored `.gitattributes`; the ordinary half-retained result stays
unchanged. This narrow probe does not establish general attribute-engine support.

## Bounded Compatibility Investigation

The separate next change will retain discriminating original probes for:

1. Uniform runs around 64-byte boundaries, distinct repeated values, termination and binary markers.
1. Random spans, single-byte edits, permutation and duplicate-span counts to separate framing,
   normalization and weighting from unexplained equivalence.
1. Competing sources with equal basenames and different scores, both with rename-only and copy
   detection, to characterize the documented preselection step.
1. Ordinary source-like and binary fixtures to assess whether remaining differences affect normal
   supported use rather than only pathological data.

Do not tune expected outputs to the draft. Keep every mismatch visible. If bounded observations and
public documentation cannot support faithful independent implementation, report the exact unresolved
cases and required decision to the coordinator. Do not accept a collision-free alternative merely
because it appears cleaner, add another algorithm solely to imitate jj, or spend indefinitely
reverse-engineering incidental behavior.
