## Contract and Draft API

`Objects::detect_rewrites` composes structural tree comparison with stored-blob inference. The
public `rewrites` module exports `Options`, `Copies`, `Limits`, `Rewrite`, `Kind` and `Error`.
Private `detect` owns candidate collection, verified blob reads, exact pairing, edited pairing and
filtering; `similarity` owns bounded span accounting. No dependencies are added. Both hash formats
preserve raw path bytes. `examples/rewrites.rs` emits NUL-delimited records from an explicit
repository and pair of tree IDs.

Deleted regular/executable blobs supply rename candidates. `Copies::Modified` adds modified-file
preimages (including mode-only modifications) and source reuse; unchanged sources are excluded.
Destinations are added regular/executable files. Symlinks and gitlinks never become records.
Structural leaf comparison covers file/directory transitions. Empty sources are excluded by default;
callers can enable exact empty matches. A 100% requested threshold requires identical object IDs.
The default edited threshold is 50%, inclusive before score rounding. Results are deterministic and
sort by destination path. Target filters apply after inference and classification, so selection does
not change competing destinations' assignments.

The draft score splits bytes at LF or 64 significant bytes, matches equal spans with multiplicity,
and divides retained bytes by the larger raw payload size. Text ignores CR immediately before LF; a
NUL in the first 8000 bytes selects binary spans that preserve CR. Edited ties currently rank
rounded percentage, matching basename, source path and destination path. Exact matching prefers an
unused deleted source, matching basename and then source path. These independently chosen details
are **not** a claim of identical Git scores or pairing heuristics.

The operation never reads attributes, performs clean/smudge/textconv conversion, or accesses an
index or worktree. Callers own configuration, scheduling, merge and copy-history algorithms. The
unchanged jj call site specifies 50% similarity, a 1000 limit, modified-file copies, no empty
sources and post-inference target filtering. Those are concrete caller policies; its heuristic
choices are not automatically requirements for this Git library. Its CLI summaries omit some copy
relationships, so CLI absence alone cannot establish the underlying copy-record contract.

- Complete the independent scoring/pairing investigation below before claiming Git compatibility.
- Native coverage, broader fault/cancellation cases and final completion checks remain evidence
  gaps. Assess those needed for safe consumer use independently of B01; they need not wait for
  heuristic parity. Existing unaffected checks can be reused.

Default bounds are 64 MiB of distinct retained blob bytes, one million span occurrences, one million
candidate pairs and 100 million conservative work units, plus the existing tree/read bounds. Edited
search rejects more than 1000 sources or remaining targets after exact matching. Exceeding a bound
returns structured failure and no partial inference; Git's CLI may instead emit an incomplete diff
with a warning. Cancellation is cooperative, checked around storage, per candidate and while
scanning/scoring. Individual reads, allocations and sorts are not interruptible. No partial
repository mutations or cleanup races arise because this operation is read-only. These bounds do not
promise an exact RSS limit or recoverable allocation failure.

## Independent Observations

Original fixtures use only public Git commands and unchanged installed jj 0.45.1. No Git, gix or
libgit2 implementation or test source was consulted. jj's own consumer call sites and tests were
inspected to identify requirements. The original generator
[`observe.py`](../../tests/fixtures/rewrites/observe.py) records Git 2.55.0 `diff-tree` and jj
`diff --summary` results, including exact tree/commit identities. Inputs are defined in the
generator.

Git's [diffcore documentation](https://git-scm.com/docs/gitdiffcore) establishes deleted and
modified copy sources, configurable similarity and basename preselection. The
[diff documentation](https://git-scm.com/docs/git-diff) establishes candidate limits, exact matching
and empty-source choices. Neither document specifies a complete score or pairing algorithm.

The initial corpus agrees for ordinary half-retained lines, growth/shrinkage around 50%, final
unterminated fragments and empty exclusion. Git and jj differ for reversed lines (Git R100, jj no
rename), CRLF-to-LF (Git R066, jj no rename), edited binary lines (Git R075, jj no rename), and 128
repeated `a` bytes changed to 64 `a` plus 64 `b` (Git R100, jj no rename). The draft span comparison
scores that last pair 50. Its cause is unresolved; the observation alone does not prove hash
collisions. Required failing filter/textconv commands in configuration do not run during the
original raw-tree observation with stored `.gitattributes`; the ordinary half-retained result stays
unchanged. This narrow probe does not establish general attribute-engine support.

## Investigation Result and Deferred Compatibility Gap

The executable draft is `d84f351d12abb9f35b7075e6a3e46cea60f07bf7`. The separate investigation
changes only probes, retained observations and evidence. The original
[`investigate.py`](../../tests/fixtures/rewrites/investigate.py) runs a bounded 168-case corpus for
each hash format using seed 180011. Each process has a 20-second watchdog. The durable
[`observed.json`](../../tests/fixtures/rewrites/observed.json) retains every original input byte,
path, tree ID, Git output and draft output. Inputs are deduplicated by SHA-256 of raw bytes, which
is distinct from Git object identity. Full standalone JSON outputs also remain in the local report.

Both formats produce identical operation outputs: 158 cases compare the rename-only draft with Git,
120 agree and 38 differ; ten additional copy-enabled Git controls have no draft comparison. Of the
38 differences, 32 concern scores and six concern basename preselection. All 40 seeded random
text-span mutations, 20 seeded random binary mutations and nine numbered source-like text cases
agree. These distributions describe this deliberately discriminating corpus, not an estimated
real-world mismatch frequency.

The score differences cannot be dismissed as irrelevant pathological content:

- 64 `a` bytes versus 64 `b` bytes produces Git R100; the draft finds no relationship.
- At 65 bytes, Git reports R098; at 96 bytes, R066; at 128 bytes, R100 again. Appending LF retains
  related differences. The full observations preserve the exact inputs and scores.
- A plausible text file consisting of `header` plus LF, 64 hyphens plus LF, and `footer` plus LF,
  changed only from hyphens to equals signs, produces Git R100; the draft finds no relationship.
- Several periodic patterns also disagree. Other controls with 64 repeated NUL or DEL bytes do not
  follow the same equivalence. Thus a uniform-run special case is not justified.

These observations separate 64-byte framing from exact byte equality but do not establish the full
internal equivalence computation. A lossy fingerprint is a possible explanation, not a demonstrated
algorithm. Public behavior documentation leaves this computation unspecified; a finite set of
examples cannot identify it faithfully. Reproducing observed examples by exceptions would weaken
compatibility rather than establish it. No source inspection or special-case implementation was
performed.

The basename result has stronger support from documentation and observations: with `-M50%`, one
source `a/file`, a 99%-similar `c/other`, and a same-basename `b/file`, Git chooses `b/file` at 75%
or greater; at 74% or less it chooses `c/other`. With `-C50%`, Git produces relationships to both
targets. The draft chooses the globally higher score. This confirms a normal supported-case pairing
gap; no general threshold formula or ambiguous-basename behavior has yet been established. The
findings remain evidence for a later correction, not a claim that this substep is implemented.

The investigation originally left R18 blocked pending a broader investigation decision. The user
subsequently chose to defer this work to B01 while retaining the draft and all observations. Restart
criteria and integration responsibilities now live in that backlog item. Do not redefine span
equality as Git parity or treat deferral as acceptance. This documentation-only disposition changes
no implementation, tests or recorded measurements and dispatches no successor.

## Draft Validation and Measurements

The draft passes 55 public integration cases in SHA-1/SHA-256, ten focused units, all 22 crate
doctests, all-feature/all-target Clippy, nightly formatting, rumdl, docs.rs and warning-denying
private Rustdoc. Markdownlint uses the user's 100-column rule with the repository's table exception.
Existing unaffected test suites are reused as authorized. Rendered Rustdoc layout was not inspected;
native Linux/Windows execution, in-flight cancellation latency, additional corruption/fault cases,
full candidate/pairing compatibility and final acceptance remain open. Portable tests are not yet
added to the native workflow while the implementation's compatibility scope is unresolved.

Commands and raw logs are retained in the local report. The benchmark command is
`cargo build --release --example rewrites` followed by `cargo bench --bench rewrites -- --noplot`.
Criterion uses 20 samples, a one-second warmup and a two-second requested measurement period.
Fixtures contain 32 distinct blobs of 24 original numbered lines; edited destinations append one
line. Setup is outside measurement. Both process adapters must emit byte-identical NUL-delimited
records before timing. Library measurements include tree comparison, verified blob reads, inference
and owned output; repository/object-view construction is outside the library timing. Process
measurements include fresh startup, repository opening and output pipes. Loose object bytes are warm
in the filesystem cache; there is no retained content cache between inference calls. Git does not
promise the draft's eager integrity checks.

The exploratory measurements below are Criterion mean estimates and 95% confidence intervals in
milliseconds, on macOS 26.6.2 arm64, Rust 1.98.1 and Git 2.55.0 with default release settings.
