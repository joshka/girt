## Public Behavior and Effects

- `Expected::Exists` and `Expected::AbsentOr(Target)` apply under destination locks, preserving
  stored-value and resolved-terminal distinctions. Format mismatches fail before locks. Predicate
  failures never become unconditional updates.
- Stored symbolic replacement/deletion with `Reflog::Append` locks old/new dependencies and logs
  only the edited name with terminal IDs. Direct, detached and unborn endpoints use the same
  format-aware old/new record contract. Resolved edits log the symbolic chain.
- `Reflog::Delete` removes the destination log after ref deletion; `LogOutcome::Deleted` reports
  absence. It is rejected for replacements. Malformed history may be explicitly deleted. Existing
  packed-first deletion and loose precedence remain; later operations can already report packed
  removal when an earlier loose publication fails.
- `ReflogRecord` retains exact imported bytes and exposes interpreted entries separately. D1's
  `+0060`, empty-name and padded-name records are accepted in both formats and remain byte-identical
  when appending. Canonical construction remains stricter.
- Windows files storage uses UTF-8 paths, explicit filename refusals and lock handles that exclude
  delete sharing. Publication uses separate same-directory temporaries while retaining locks. Unix
  checks lock identity before publication/cleanup. Cleanup is best effort; exit leaves a stale lock
  for caller-authorized recovery. No global signal policy or fsync guarantee is introduced.
- Errors retain I/O sources and existing structured preparation/publication outcomes. Existing
  transaction tracing reports categorical failure and possible partial effects without recording
  names, identities or log messages.

The changed owning modules are `refs::store`, `refs::transaction` and `refs::reflog`; public exports
remain under `girt::refs`. The executable `reference_transaction` example includes absent-or-same
retention and explicit ref/log deletion. No dependencies were added.

## Git, Fault and Grammar Evidence

`tests/references_portable.rs` exercises SHA-1/SHA-256 imported records, retained bytes plus append,
packed-only and shadowed deletion, competing conditional writers, a prepared Git writer holding a
real ref lock, and symbolic unborn HEAD log IDs compared with Git's `symbolic-ref -m` result.
Windows adds filename-refusal cases. Existing unit suites cover namespace/overlap conflicts, packed
publication failure, later-ref failure, partial append byte counts, symbolic dependencies, lock
contention, and cleanup. New tests add log-deletion failure with published-ref outcomes,
replacement-lock protection, and subprocess exit/stale-lock recovery. Existing Unix reference
integration cases remain in the full suite.

The external [lexical probe](r11-observations.json) records 24 both-format observations; the
[grammar/resource probe](r11-grammar.json) records 12 more. Retained Python scripts and the
independent public-API harness permit reruns. Noncanonical four-digit zones, empty email, negative
seconds and leading zeros agree within the reader's interpreted range. Exact retained bytes include
each accepted record's original spelling. A 1 MiB message parses and retains its bytes in both
formats; this is a boundary observation, not a memory-budget guarantee. Whole-file reads remain
allocation-proportional without configurable limits.

Git also consumes records outside this reader's boundary: unterminated lines, CR/NUL messages, short
zones, zone suffix text and seconds beyond `i64`. Git's displayed message/date can differ for these
inputs. R11 deliberately retains explicit refusals, complete-record append validation and canonical
construction; it does not claim exhaustive imported-reflog grammar parity. Broader consumer-required
interpretation belongs to R14 characterization before R34 readiness.

## Performance

Criterion ran on local macOS arm64, Rust 1.98.1, warm local storage, 30 samples, 1-second warmup and
2-second target measurement. Fixture generation remains outside measured operations. The retained
[final benchmark log](r11-bench.log) was collected without concurrent local builds/tests, at the
same executable implementation as `fbbc1539`.

| Operation                                 | Estimate  | 95% interval     |
| ----------------------------------------- | --------- | ---------------- |
| Read packed ref among 10,000              | 3.1874 ms | 3.1549–3.2317 ms |
| Delete shadowed ref among 10,000 packed   | 4.0492 ms | 4.0165–4.0982 ms |
| Keep-same batch of 100 with 10,000 packed | 39.390 ms | 39.120–39.674 ms |

Command:

```sh
cargo bench --bench references -- \
  'references/(read-packed-warm-10000|delete-shadowed-packed-10000|keep-same)' --noplot
```

Earlier pilot logs remain retained; their comparison labels are not performance claims. No cold-I/O,
allocation-budget or numerical regression threshold is established.
