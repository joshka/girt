# R20 Linked Worktree Administration

## Scope

Executable revision: `f8aaa936ab877243faf9c8a94d106e595fe06b75`, following the separate R19
acceptance change `09a115f2`. No jj consumer or dependency changed. The R18/B01 draft remains
unaccepted and does not gate this work.

`Repository::repair_worktree` takes an explicit registration and existing checkout, checks the
current forward link, and replaces `commondir`, `.git`, and `gitdir` in order. It supports files and
reftable, both object formats, and the common repository's relative path setting. Native Windows
path serialization uses the R19 helper that removes verbatim prefixes. `lock_worktree` and
`unlock_worktree` manage Git's `locked` file. `prune_worktree` removes one registration only when
its `gitdir` timestamp predates the caller's expiry, its target is absent, and no lock is present.
An unreadable target is uncertain. A private `girt-admin.lock` excludes cooperating calls; a crash
leftover is retained and blocks subsequent administration until inspected. The caller still owns
checkout and jj workspace materialization, and excludes noncooperating Git administration and moves.

Repair errors distinguish refusal/uncertainty from I/O and report each successfully replaced path.
Temporary replacement files may remain after failure. Prune I/O failure can leave a partly removed
registration; retry requires inspection. Neither operation promises crash durability or discovers a
moved checkout from its stale backlink. The caller must supply the moved location for repair before
pruning; this is material to preservation of a live moved worktree and its private roots. Git's
private `HEAD`, index and refs are not altered by repair. A registration's private metadata is
removed by successful prune; lock and expiry are the caller's retention controls.

## Local Evidence

On macOS arm64, Rust 1.98.1 and Git 2.55.0, six focused public cases pass. They cover moved common
repository and checkout for SHA-1/files and SHA-256/reftable, a moved checkout under relative links,
Git `symbolic-ref`/`status` after repair, live/locked/nonexpired prune refusal, expired stale prune,
foreign-link refusal, a retained crash lock, and a Unix permission failure before link replacement.
The earlier R19 suite still passes. The broad all-feature runtime suite passed before the final
additional focused refusal and permission fixtures; the final six-case suite and
all-feature/all-target Clippy pass. `just docs-rs` and `just fmt` pass. The repository's roadmap
table has two pre-existing global markdownlint line-length diagnostics; `rumdl check .` passes.

D4 inventory now checks each `commondir` link against the already-open common repository instead of
reopening every linked repository, so it avoids repeated common configuration and shallow reads. It
retains individual link errors; callers can fully open a selected private repository when needed. On
the same warm 10/100/1,000-registration Criterion workload and macOS host as R19, 95% intervals are
818.98–837.04 µs, 8.3434–8.5753 ms and 88.527–91.863 ms. R19's prior intervals were 2.0795–2.2462
ms, 20.849–21.684 ms and 216.51–220.54 ms. These are warm inventory measurements, not end-to-end jj
latency. Benchmark source fingerprint remains
`97797d4c193a3eddb479501305f3c6aaed1438294ce9c269771b169e2b1ea1ed`; new inventory source fingerprint
