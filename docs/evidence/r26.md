# R26 Remote Discovery Evidence

R26 adds read-only discovery before fetch or clone decisions. `RemoteDiscovery` carries validated
refs, raw capability tokens, the SHA-1 or SHA-256 object format, a protocol family, and an explicit
HEAD state. `RemoteHead` distinguishes symbolic, unborn, unhinted unique-match, detached, missing
and ambiguous results. The unhinted result is a candidate, not proof that HEAD is symbolic. Clone's
default policy still keeps an unhinted HEAD detached, and an empty v0 advertisement without an
unborn hint retains its documented `main` fallback. A caller can require the discovered format
before preparing a destination; a mismatch reports both formats. `supports_current_fetch`
distinguishes peer-advertised features from girt's currently usable pack-request path. Discovery has
no local mutation.

Native local discovery uses repository and reference APIs directly, includes verified tag peel
hints, and reports an unborn symbolic HEAD even with no refs. It checks that a directly read local
HEAD matches the advertised tip, and reports it detached even when a branch shares that ID. The HTTP
and Unix SSH adapters use their configured trust, authentication, redirect, interruption and cleanup
paths. They currently request protocol v0. A caller-owned upload-pack stream accepts v0 or v1
advertisements and v2 capabilities followed by one bounded `ls-refs` request. V2 requests `peel`,
`symrefs`, and `unborn` only when the server offers it; SHA-256 adds the required
`object-format=sha256` request line. Unknown v2 ref attributes and unsupported negotiation are
rejected. The owned HTTP/SSH transfer operations still use SHA-1 v0 and refuse SHA-256 before
sending wants or changing local storage.

## Git Observations and Fixture Provenance

`tests/discovery.rs` creates fresh bare SHA-1 and SHA-256 repositories with Git, then creates an
empty tree and a commit through Git commands. It feeds Git 2.55.0 `upload-pack --stateless-rpc`
v0/v1 advertisements and v2 capability/`ls-refs` results to the public discovery APIs. Git v0
advertises an empty SHA-256 repository with a zero ID and `capabilities^{}`; it does not identify
the unborn branch. V1 prefixes `version 1`. V2 advertises `ls-refs=unborn` and
`object-format=sha256`; its `ls-refs` response names the unborn HEAD symbolic target when the client
requests `unborn`. The tests compare the exact request generated by girt with the request answered
by Git, and check both empty and populated HEAD results in both formats. Local discovery adds the
branch name from the repository's HEAD target rather than guessing from the v0 marker.

The HTTP integration suite uses the original loopback Git `http-backend` fixture for both object
formats and verifies that discovery sends only its GET. The Unix SSH suite uses its isolated sshd
and forced Git service for both formats, checking that a discovery-only session exits without a
pack. Unit cases cover conflicting symbolic hints, ambiguous unhinted HEAD, duplicate/unknown
format, and cancellation and byte/ref bounds. The tracing suite checks categorical discovery spans
without emitting ref bytes or paths. `benches/fetch.rs` adds a 10,000-ref v0 discovery case to the
existing Criterion workload; its generated packet source is original and reproducible.

## Validation and Remaining Scope

The exact tested code revision is `5fb038e99abfab5ce2b59b23aa720b1addf0c246`, published at
`joshka/r26-discovery`. The first evidence revision was `ba12ad9f7324d64911bab4351a1454e8adedab2e`;
the B06 follow-up remains in this documentation change. On macOS 26.6.2 arm64 with Rust 1.98.1 and
Git 2.55.0, `just check` passes nightly rustfmt, rumdl, the all-feature test suite and doctests,
all-target Clippy with warnings denied, and the docs.rs build with Rustdoc warnings denied. Focused
core-only, HTTP-only, SSH-only and all-feature discovery tests also pass. The workflow's portable
discovery suite is selected explicitly on Windows; Unix full and HTTP/SSH-only suites exercise the
endpoint cases.

`cargo bench --locked --bench fetch -- discover-v0-10000 --noplot` measured a warm, in-memory
10,000-ref v0 packet fixture on that revision. Criterion 0.8 collected 30 samples; the median is
3.866 ms with a 95% confidence interval of 3.782–3.969 ms, or approximately 2.59 million refs/s. The
benchmark excludes network, repository opening and allocation of its input bytes. Retained
[samples](../benchmarks/r26-discovery/discover-v0-10000-sample.json) and
[estimates](../benchmarks/r26-discovery/discover-v0-10000-estimates.json) support comparison. This
is a parsing baseline, not an end-to-end transfer or memory bound. Discovery's wire and ref limits
have separate rejection tests.

The [origin platform run](https://github.com/joshka/girt/actions/runs/36232998305) uses the exact
tested code revision. Its first attempt passes on Windows Server 2022, macOS 14 and Ubuntu 24.04.
Ubuntu 22.04 initially stops in the unchanged
`remote::credential::tests::failed_helper_allows_later_helper` unit: its synthetic helper exits
before consuming stdin and the writer observes `Broken pipe`. A failed-job-only second attempt
passes Ubuntu 22.04's all-feature suite, including discovery, then fails at the previously recorded
`http::abandoning_download_on_worker_closes_original_spans` tracing assertion because it captures no
`fetch.http` span. Thus R26's discovery cases pass natively on all four hosts, while the overall
platform workflow remains failed. R22 owns the credential-helper race through
[B06](../jj-roadmap.md#b06--credential-helper-early-exit), which requires checking real helper
fallback semantics and escalation if they are affected, and
[B04](../jj-roadmap.md#b04--intermittent-tracing-and-split-index-assertions) owns the tracing
investigation; neither result is counted as a discovery failure. Windows SSH runtime remains
unsupported under R24. This finite corpus characterizes Git 2.55.0 behavior, not every server
implementation.

R27 owns have/want rounds, shallow/depth requests, thin-pack characterization and pack receipt. R28
owns refspec mapping, installation, prune and conditional outcomes. R29/R30 own expanded push
commands, protocol status and policy. R35 must assess the actual endpoint set used by the target jj
integration. A v2-only HTTP or SSH endpoint would require an owned v2 discovery/RPC path before that
endpoint can be accepted; the current owned adapters request v0 and explicitly reject a v2 response.
Discovery previews are stale after their session and never authorize transfer or ref publication.
Cancellation is cooperative between synchronous local or caller-owned stream I/O; owned network
waits use their existing deadline and process cleanup contracts.
