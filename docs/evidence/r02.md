# R02 — Format-Aware Identity and Hashing

R02 implements the identity/hash portion of
[A02](../jj-acceptance.md#a02--object-format-and-identity-foundations). Repository storage, codecs
and transport remain SHA-1-only. R01 is preserved at `78a702e6d4831b9db5f31a4c140ada31da7e9b6b`; no
jj consumer changes, publication or merge are included.

## Public API

`ObjectId` is a closed enum with `Sha1([u8; 20])` and `Sha256([u8; 32])`. Derived equality, ordering
and hashing include the variant and exactly its meaningful bytes. Ordering puts SHA-1 first, then
compares bytes lexicographically within each format. Identities establish neither existence nor
kind.

- `ObjectId::from_bytes(format, bytes)` checks raw length; `as_bytes()` returns a 20/32-byte slice.
- `FromStr` recognizes full 40/64-digit hexadecimal identities. `from_hex(format, value)`
  additionally requires the chosen format. Both accept ASCII uppercase and lowercase; display emits
  lowercase.
- `format()`, `null(format)` and `is_null()` expose format and format-specific absence sentinels.
- `ObjectId::for_blob(format, bytes)` and `ObjectFormat::hash_object(kind, bytes)` hash canonical
  Git framing with exact payload bytes. `ObjectFormat::digest_len()` reports raw width.
- `ObjectFormatError { expected, actual }` identifies unsupported ID inputs through domain error
  variants. Checkout boxes its nested status-verification cause to avoid growing every result with
  the larger identity representation. No compatibility aliases, padded identity comparisons or
  format registry are added.

The types remain re-exported from the private `object` module. Existing callers now select SHA-1
explicitly or construct the exact `Sha1` variant. The general hashing API accepts `ObjectKind`; it
does not validate embedded references, translate hashes or promise collision detection. Existing
immutable decoded `Object`, `Tree`, `Commit`, `Tag` and `Index` values remain SHA-1-specific.

## Independent Compatibility Evidence

The original [Git probe](../../tests/fixtures/objects/observe.py) invokes `git init` and
`git hash-object --stdin --literally -t KIND` in disposable SHA-1/SHA-256 repositories with
inherited Git overrides and global/system configuration disabled. The
[retained observations](r02-git-observations.json) record payload hex, identity, Git version and OS.
No upstream implementation or test source was used.

The public `tests/object_ids.rs` suite checks twelve independently observed hashes: empty, text and
all-byte blobs, an empty tree, and literal arbitrary commit/tag payloads in both formats. Literal
hashing tests framing, not commit/tag validity; fsck of those payloads is inapplicable. Existing
SHA-1 storage interoperability and strict-fsck tests still exercise valid object workflows.

Local tests cover exact/raw widths, hex widths and invalid bytes, uppercase input, format mismatch,
nulls, equal prefixes, trailing digest bytes and mixed-format hash/ordered maps. Refusal tests cover
SHA-256 tree/commit/tag/index construction, loose reads before missing-path access, pack/index
outputs before writes, reference edits/expectations before locks, fetch advertisement/selection
before request bytes, push commands before graph reads, and equal-root tree comparison. The public
repository case checks read refusal and checkout refusal before an existing foreign index lock.

Reference transactions preflight every edit before any lock. Codecs retain immutable validated
entries so subsequent encoding cannot introduce an unchecked SHA-256 ID. The SHA-1 text parsers keep
their width restriction instead of inheriting broader `ObjectId::FromStr` acceptance. Untagged
binary tree/index/pack bytes do not permit reliable format autodetection; those APIs continue to
require SHA-1 input according to their contracts.

Refspec name mapping is pure and format-independent; its zero-ID check now respects either format.
Repository-backed operations still reject SHA-256. No dual-hash translation is introduced.

## Validation and Performance

The [retained validation record](/Users/joshka/.codex/reports/girt-r02/validation.json) records the
exact completed revision, source fingerprints, commands and log paths without a self-referential
commit hash. `just check` passes with 1,287 unit tests, 551 integration cases and 20 doctests,
all-feature/all-target Clippy and docs.rs with warnings denied. Native execution is on macOS arm64
with Rust 1.98.1 and Git 2.55.0. Linux/Windows native evidence remains open; the portable
`object_ids` suite is selected in Windows CI. Cross-compilation is supplementary.

The Criterion blob harness now measures both SHA-1 and SHA-256 hashing over 64-byte, 4-KiB, 64-KiB
and 1-MiB repeated/pseudorandom payloads. It includes header creation and hashing, with setup
outside timing. Run `cargo bench --bench blobs -- hash`; retained results and environment are in the
run record. For pseudorandom payloads, mean SHA-1 times are approximately 190 ns (64 bytes) and
1.071 ms (1 MiB); SHA-256 times are 413 ns and 3.023 ms. Confidence intervals for all sixteen
workloads are retained. No numerical regression threshold or comparative speed claim is established.

`sha2 = "0.10"` adds the SHA-256 implementation; the resolved 0.10.9 package declares
`MIT OR Apache-2.0`, inspected in its registry manifest. Its digest/CPU dependencies were already
present. In-memory hashing has no new filesystem fault, concurrency or cancellation lifecycle;
existing storage race/fault tests continue to apply. Input payload memory belongs to the caller;
hashing retains bounded digest state plus the small object header, without copying the payload.
