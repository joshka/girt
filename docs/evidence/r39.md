# R39 Alternate Object Stores and Known Extensions

## Acceptance Contract

R39 extends the accepted R14 executable and separate HTTP repair. Its documentation parent records
coordinator acceptance at `d11d40c071cc292d8d4d19407ec2a1936807690f`. Historical HTTP failures and
C02's independently reproduced missing tracing span remain in their original reports.

Deliver both-format primary and alternate loose/packed reads, moved relative graphs, nested/shared
stores, missing-then-valid fallback, canonical cycle/alias termination, native paths, and explicit
corruption/I/O/resource failures. Recognize known extensions without fetching missing objects or
modifying borrowed stores. Validate against original Git observations and affected native tests;
reuse R14's unaffected legacy-codec, reference and index evidence. R15 retains file-backed pack
storage and R16 retains refresh.

## API and Topology Contract

`Repository::objects` now discovers local alternates with default `AlternateLimits`.
`Repository::objects_with_alternates` accepts custom graph limits. The private `objects::alternates`
module owns iterative discovery and path decoding. `ObjectReadError::Alternate` retains the metadata
path and rejection reason. No dependency is added.

The reader visits the primary then each alternate depth-first in file order. Each store searches
loose objects before filename-ordered packs. A corrupt candidate fails immediately; it does not fall
through to a later duplicate. Pack validation remains eager, so a corrupt indexed pack can prevent
opening even if an object would be available elsewhere. Missing alternate directories are skipped;
other filesystem failures preserve their path and `io::Error` source. Canonical aliases and cycles
are visited once. Missing-object cycles terminate without a negative cache.

Relative paths resolve from the borrowing object directory. Records use LF separators; CR is a
literal path byte. Empty lines and leading-`#` comments are ignored. Quoted paths decode C escapes
and three-digit octal bytes. Unix paths preserve bytes; other platforms require UTF-8 metadata
paths. NUL, empty quoted paths, invalid escapes, unfinished quotes and trailing bytes after a
closing quote return explicit metadata errors. Git's observed NUL truncation and malformed-record
skipping are deliberately not reproduced: silently reading a different path would obscure invalid
metadata. No environment or tilde expansion occurs. `GIT_ALTERNATE_OBJECT_DIRECTORIES` and
`GIT_OBJECT_DIRECTORY` remain ignored under the existing explicit repository-opening policy. HTTP
alternates metadata is inert during local reads.

The repository supplies one object format for the graph; bare object directories have no format
marker. Wrong-format bytes fail existing identity/pack validation. Thin stored packs still require
their base in the same pack. Unknown repository extensions remain unsupported. `noop` accepts its
value without interpretation, `preciousObjects` validates a Boolean and remains available through
`Repository::config`, and `partialClone` requires an explicit value. Local reads never fetch a
promised object: absence is `Ok(None)`. R26/R27 retain promised-object transport, and R31–R33 retain
precious-object deletion protection. No pruning API is introduced.

Topology and pack data remain fixed for one reader; loose files remain live. Reopening observes
alternate edits. A concurrent edit during opening can produce mixed topology or an explicit error;
there is no atomic filesystem snapshot or retry loop. Callers needing consistency must exclude
writers. R16 owns coherent refresh and retained-reader publication behavior. All discovery and reads
are synchronous; no deadline interrupts a blocked filesystem call. Paths and ancestors must be
trusted, consistent with existing loose storage.

## Resource and Ownership Bounds

Defaults permit 1,024 canonical stores including the primary, 4,096 path records including aliases
and missing paths, 1 MiB aggregate metadata, and 4 MiB cumulative input/canonical path bytes. Path
accounting occurs before joining records and before retaining canonical paths. Canonicalization
itself temporarily allocates an OS-resolved path. Metadata reads use a one-byte overflow probe. Only
one metadata file is open at a time; traversal uses a heap stack, never recursive calls.
`PackLimits` now charges pack count and artifact bytes across the entire graph. Limits are input and
retained-work bounds, not a total process RSS quota. R15 owns pack/index memory and descriptor
budgets, including cancellation policy for expensive opening.

`Objects` exposes reads only. `Repository::loose_objects` still writes solely to the primary object
directory. Borrowed trees are compared byte-for-byte before and after reads and primary writes. This
does not claim protection against hostile symlink replacement or filesystem access-time changes.

## Original Evidence and Validation

The [Git repository layout specification](https://git-scm.com/docs/gitrepository-layout) defines
relative object-directory paths. The
[original CLI generator](../../tests/fixtures/alternates/observe.py) and
[retained observations](r39-observations.json) cover path framing and known-extension values in both
formats with Git 2.55.0. No Git/gix/libgit2 implementation or test source was consulted. R14's
unchanged Git/jj consumer observations remain applicable to extension acceptance and imported
objects. New public-API fixtures generate their own Git repositories and pack artifacts at runtime.

The first executable revision is `6fab9ff5990a5526b49554ecd15601a7e6fdc11b`, published only through
`joshka/r39-native-validation` to origin. Its
[first native run](https://github.com/joshka/girt/actions/runs/36160952958) is retained. Local
`cargo test --all-features` passes 1,625 units, 1,092 integrations and 20 doctests. `just check`
then stops at Clippy's non-octal permission literal in the new test; it is not recorded as a full
passing command.

The correction at `6b8c5973325c` fixes an intermediate `u8` overflow when decoding high octal bytes
and uses an octal permission literal. A platform-independent `\377` regression passes, and the pack
tests additionally check aggregate budgets across primary and alternate copies. Final local checks
pass all 14 path-parser cases, 32 alternate integrations, all-target/all-feature Clippy, scoped
Clippy after the aggregate assertions, docs.rs, private Rustdoc and formatting. The full suite's
unaffected evidence is reused. Native verification is pending at the corrected revision.

The macOS APFS host rejects the non-UTF-8 filename fixture during setup with OS error 92
(`Illegal byte sequence`). That initial local failure prompted Linux-only filesystem byte-name
coverage, consistent with existing repository tests. macOS still checks byte decoding, quoted paths
and symlink aliases. Linux must execute the full filename case; compilation is not evidence.

A separate `/usr/bin/time -l` invocation of the exact `bounded_shared_graph_workload` test opens 513
canonical stores with 1,024 graph edges and 12,178 metadata bytes in 25.344 ms. Maximum RSS is
8,306,688 bytes for the complete test process, including runtime and fixture construction; it is not
isolated reader allocation. This single warm local observation establishes no speedup claim or
cold-filesystem guarantee. The workload verifies a successful missing-object lookup, graph
termination and rejection at 512 stores. Default record, metadata, resolved-path and aggregate pack
limits have separate boundary tests. Filesystem calls are synchronous and cannot be interrupted by
these input bounds.

## Remaining Ownership and Limitations

R15 owns whole-pack allocation, bounded file-backed index/cache/descriptor accounting across the
graph and its opening cancellation policy. R16 owns refresh, publication races and retained-reader
lifetimes. The R39 contract deliberately exposes fixed topology with live loose files; the test
edits metadata from a joined writer after snapshot construction and verifies old/new reader views.
It does not establish transactional topology when edits overlap opening.

C02 retains native Windows ACL-denial and UNC/drive-alias expansion beyond the portable native path
and directory-I/O failures exercised here. Unix permission-denial tests preserve `PermissionDenied`.
Windows metadata paths require UTF-8; Unix non-UTF-8 names depend on filesystem support. Native
symlink creation on Windows is not claimed. These bounds do not defend against hostile path
replacement. Malformed alternate records fail explicitly even where Git skips/truncates them.
R26/R27 retain promised-object fetching; R31–R33 must honor precious-object protection before any
future pruning. R37/R38/R40 and the C02 tracing finding keep their existing owners. No successor,
merge or release is dispatched.
