repositories. Run `python3 tests/fixtures/external-storage/observe.py` to reproduce the JSON matrix.
The [retained matrix](r14-observations.json) contains 64 observations. Every case runs in SHA-1 and

Girt currently permits object directory symlinks through ordinary filesystem resolution; this is not
protection against hostile replacement. R39 must preserve the external store's ownership and avoid
writing borrowed objects. R15 owns file-backed reads and memory/cache/descriptor budgets; R16 owns
refresh, publication races and retained-reader lifetimes. Neither is implemented here. Thin-pack
reception and external delta repair remain R26/R27; local stored packs in this corpus are
self-contained. R14 does not infer local thin-pack support from transport acceptance.

## Imported Reflogs and Colocation

The original fixtures include CR and NUL messages, an unterminated final record, short and suffixed
zones, seconds beyond signed 64-bit range, and a 1 MiB message. Git's `reflog show` consumes these
forms with differing display behavior; the exact output is retained. jj imports and reports status
successfully for every case. These workflows do not prove that jj interprets each imported record:
production consumer inspection finds reflog construction policy, not direct reflog iteration.

R11's strict reader remains narrower than Git, and reads the whole file without a configurable
budget. GC in R31 must consume imported logs to preserve roots; therefore R40 is required before R31
rather than dismissing these differences as unused. R40 must separate raw record iteration,
interpreted timestamps and safe append construction. It must preserve exact bytes and recoverable
object roots, bound file/record/retained bytes and cancellation, and define truncated/malformed
record recovery without silently dropping retention roots. Test these original records in both
formats, append against unusual preexisting tails, large logs, I/O faults and native platforms.
Canonical append validation must not be weakened to obtain permissive reads.

The consumer's `reset_index` builds an index from its merged parent tree and reuses stat data;
`update_intent_to_add` owns placeholders. Working-file snapshot and materialization remain jj-owned.
No additional girt raw status/checkout call requirement was found in the inspected production
consumer. R13's explicit flag editing is sufficient for that boundary. Raw flag support is not
claimed; C02 retains Windows raw-workflow assessment and R35 must repeat the call-site inventory.
R38 must test actual split/sparse reading and publication, shared-file absence/corruption, sparse
tree expansion, flags and races. Its requirement is not closed by jj's initialization succeeding.

## Delivered Behavior and Validation Contract

`Repository::objects` now reads pack v2/v3 and index v1/v2 with both object formats. The private
`pack::index` parser validates v1 framing, exact size, sorted unique identities, fanout, offsets,
coverage and checksums. Both versions share offset ordering and fanout validation. A v1 entry has no
CRC; the reader still validates pack/index checksums and reconstructed object IDs. Unknown versions
remain explicit errors. Pack writing and transport import keep their existing contracts.

Original units cover valid legacy reads, incorrect fanout/count/offset, truncation and checksum
damage. Six public-API integrations cover legacy versions with both hashes and REF/OFS deltas,
compare complete payloads against independently generated records and ask Git to read a delta. Two
Unix public-API integrations reopen symlinked object stores. Existing corruption, decode-budget and
delta-cycle cases remain applicable. No new processing algorithm or performance claim is introduced;
R15 retains meaningful file-backed resource benchmarks.

## Required Queue and Completion Boundary

Recommended serial order is R14 → R39 → R15 → R16 → R37 → R38 → R40 → R17, then the existing queue.
R39 depends on R14; R15 additionally depends on R39 so file-backed resource accounting covers all
searched stores. R37/R38 keep their existing ownership and run before C02. R40 depends on R11 and
R14 and runs before C02/R31. C02 reviews these storage changes together. R34 depends on all four
follow-ups, not just explicit refusal documentation.

R39 must deliver both-format primary/alternate loose and packed reads, relative resolution after
moves, nested and shared alternates, missing-then-valid fallback, cycle/alias bounds, symlinks and
byte/native paths. Define precedence, corrupt duplicate behavior, aggregate traversal limits,
external ownership and explicit environment policy. Add known-extension handling for noop,
preciousObjects and complete partial-clone stores without implying lazy fetching. Prove no writes or
pruning in borrowed stores. Exercise Git/jj controls, malformed path records, permissions,
concurrent alternate edits, native Windows/Linux/macOS and independently measured resource bounds.
Refresh implementation stays in R16; R39 supplies its store topology contract.

R37 must import nonempty reftable refs/reflogs and publish conditional updates with Git-readable
stack/compaction results, faults and native evidence. R38 must preserve or deliberately replace
split/sparse state through public index/colocation APIs with both-format Git observations and native
evidence. Their existing roadmap tasks remain required even where baseline behavior is incomplete.
Unknown extensions, promised-object fetch and accelerators are not silently classified as
implemented.

Validation results and exact publication revision are recorded after checks complete. R14 remains in
progress until the bounded executable changes have native evidence and coordinator review.
