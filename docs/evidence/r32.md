# R32 Additive Repack and Publication Evidence

## Delivered Boundary

`Repository::repack_retained` takes a retention policy, bounded writer options and a cancellation
flag. It runs a new complete retention scan, opens pinned source packs, fully validates every
required object during planning and writes a pack v2/index v2 pair into temporary files in the
primary pack directory. Both files are synchronized before publication. The pack is published
without clobbering an existing path, then its index is published as the visibility marker. An
existing checksum-named artifact is reused only after byte comparison. SHA-1 and SHA-256 preserve
object IDs. The operation never removes old packs, loose objects, reflogs or alternate data.
Protected packs remain untouched. New readers can open the new pair; existing readers refresh
explicitly.

The API performs an additive repack rather than a space-reclaiming replacement. This is the safe
publication slice while R33 owns pruning, reflog mutation and old-generation retirement. The scan is
a live observation. Callers must exclude cooperating writers for a stable maintenance view; girt has
no lock that excludes arbitrary external Git processes. Concurrent writers cannot lose objects
through this operation because it performs no deletion. If input disappears or changes, planning or
reading fails. No pack generation comparison is needed to authorize this additive publication; R33
must rescan roots and recent data, verify relevant generations, and account for pinned readers
before removing owned storage. Windows handle semantics are respected by retaining old artifacts
rather than unlinking or replacing them. External pack edits in place and unreliable network
filesystem publication remain outside the storage contract.

## Failure and Resource Contract

Cancellation, incomplete planning, missing/corrupt required objects and input limits fail before
publication. Temporary files are removed on ordinary errors. A failure after pack publication may
leave an unindexed pack that readers ignore. Cancellation after index publication returns success.
Conflicting existing artifacts are never overwritten. File content synchronization precedes each
publication, with directory barriers ordering pack/index visibility and retirement. These barriers
are tested under the conditional persistence model; physical power-loss durability is not measured.
A process crash can leave temporary files. No reflog expiry or destructive pruning is performed.

Default writer bounds permit at most one million input objects, 64 MiB per payload, 512 MiB total
decoded input, 512 MiB pack output and 64 MiB index output. The implementation holds fresh decoded
payloads until writing finishes, plus the retention plan, writer metadata and decoded objects in
flight. Reused entries preserve their stored compressed streams. Temporary disk use for one attempt
is bounded by the pack and index limits, plus any previously published or crash-left artifacts.
These are explicit limits, not measured peak RSS or a total process heap bound. The integration test
checks reported pack/index lengths against filesystem lengths and checks that success leaves exactly
two files in the initially empty pack directory. The Criterion workload measures an idempotent warm
repack of a 256-commit packed history, including a fresh scan, decode, compression, temporary files,
sync and byte comparison with the already published pair. It does not measure cold storage or first
publication latency.

On macOS arm64, the 20-sample idempotent repack estimate was 34.234 ms (32.581–36.378 ms). A
separate `time -l` run of the benchmark process measured 20,119,552 bytes maximum resident set size;
this includes Git fixture setup, Criterion and the process runtime. Its repeated repack estimate was
34.534 ms (33.646–35.618 ms). These observations do not establish peak heap for the largest allowed
input. The size limits and controlled early-refusal cases establish the per-attempt temporary-disk
and decoded-payload bounds.

## Initial R32 compatibility and validation

`tests/retention.rs` builds both-format original repositories using Git `init`, `mktree`,
`commit-tree` and `update-ref`. After girt publishes the pair, `git verify-pack -v` validates the
index and pack, and `git cat-file -t` reads both commits. The test removes their disposable loose
copies and repeats Git reads, then reads through a refreshed pinned girt reader. An idempotent
second publication retains the checksum. Focused cases reject incomplete scans, cancellation and
writer limits before publication. Local unit tests deterministically cancel between pack and index
publication and verify the unindexed state; a conflicting existing path preserves its old bytes. The
broader R31 suite continues to exercise kept packs, alternates, reflogs and incomplete roots.

Local `cargo test --all-features` passed 1,860 unit tests, all integration suites including 24
retention cases, and 25 doctests. The later deterministic writer-race unit passed in a focused
three-case run. `cargo test --no-default-features --test retention`, all-feature/all-target Clippy
with warnings denied, nightly formatting and docs.rs with warnings denied passed. The final
artifact-size assertion passed both-format focused tests and test-target Clippy. Initial
`just check` reached Clippy after the broad tests and failed on a needless borrow in the new unit;
the fix passed focused tests and the full Clippy/docs gates. These results are macOS local evidence;
the final native [focused validation run](https://github.com/joshka/girt/actions/runs/36260625059)
passed retention integration cases and focused no-default-feature Clippy for executable revision
`3eb9b07ec19dffeedf4f78f8dd9b8b30e5d50df2` on Ubuntu 22.04, Ubuntu 24.04, macOS 14 and Windows 2022.
Each host used Rust 1.98.1 and Git 2.55.0 (2.55.0.windows.5 on Windows). Native Windows publication
and reopening passed with old pack paths retained. The validation bookmark is
`joshka/r32-native-validation`; it was pushed for evidence, not merged or released. This report's
follow-up documentation revision records that result without changing the tested executable.

This section records the initial R32 publication work. R33 subsequently added destructive pruning,
reflog expiry, generation retirement and maintenance composition. The current entry-reuse and
retirement contracts are described below.

## Pack entry reuse

Repack fully decodes required objects during its retention scan, then copies stored entries only
from the primary object store. A delta keeps its compressed instructions when its base from the same
source pack has already been emitted; its header becomes an OFS_DELTA with the new distance. Other
deltas are materialized. Fresh objects use bounded delta search and OFS framing, so their next
repack can preserve the same bytes. Copied payloads count against logical byte limits.

Additive repack includes protected objects. Retirement omits an object only after reading a
protected copy, including one appearing later in primary lookup order, and verifies it again from a
pack protected in both observations before deleting old artifacts. Recent packed objects and their
dependency graphs remain required. The scans after publication and full survivor reads guard
deletion. If a recent object already has a missing dependency, planning refuses maintenance. Git
2.56 GC can retain that incomplete object and continue; girt deliberately keeps the stricter
complete-walk rule so it cannot authorize deletion from an incomplete retained graph. Directory
barriers order pack/index publication, multi-pack index removal, and index/pack retirement.

The [combined measurements](23-combined/README.md) record three locked, rotated rounds on the bare
131,152-object jj-vcs/jj fixture. At reviewed production revision `e0b15abf` (measured head
`408dc831`, with only a test helper gate added), repack was 7.38 s median and full maintenance 51.63
s; Git was 1.43 s and 1.53 s. A complete scan took 6.32 s median. The retained raw records identify
revisions, cache conditions, RSS and run order. The old-pack repack target is met; maintenance
leaves limited headroom below 60 seconds. Recent-pack dependency closure adds scan work and is
measured separately alongside protected/changing-root sequences.

### Earlier implementation measurements

The original [#47 (Opus low)](https://github.com/joshka/girt/pull/47) measurement used the same bare
clone plus 150 loose objects on a new branch, before equal-root walk reuse: repack 21.6 s / 430 MiB,
pack retirement 52.7 s / 437 MiB, about 19 s per scan, and a 205,750,868-byte replacement. Git
repack was 1.6 s / 288 MiB with a 205,693,617-byte pack. Git integrity checks passed on those
outputs. These are historical observations of a different workload, rather than the combined
implementation's current timings. Further scan reductions are tracked in
[#24](https://github.com/joshka/girt/issues/24).
