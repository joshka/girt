# R37 Reftable Acceptance Plan

R37 is in progress. No reftable implementation or parity evidence is claimed by this plan. R16
coordinator acceptance is the separate parent change `5ef523dc96468e0deaf35c34ae6152dd8885d2bc`. The
executable specification input is the published
[reftable format](https://git-scm.com/docs/reftable); compatibility fixtures must be generated
independently with Git commands and original byte encoders. Upstream implementation and test sources
are excluded.

## Atomic Stages and Acceptance

1. **Record codec:** Read and write SHA-1 version 1 and SHA-256 version 2 headers, reference
   records, peeled values, symbolic values, deletion records and compressed reflog blocks. Validate
   footer CRC, block framing, restart offsets, key order, update indexes, truncation, integer
   overflow and bounded decompression. Exercise aligned and unaligned tables, indexes, log-only
   tables and empty tables from independently generated Git repositories.
1. **Stack reads:** Parse bounded `tables.list` entries without path traversal, merge references and
   reflogs by stack precedence, apply tombstones, preserve record ordering, and read coherent pinned
   generations during publication and compaction. Specify cancellation, byte, record, table and
   handle budgets; test missing/replaced tables without hidden unbounded retries.
1. **Publication and compaction:** Hold Git-compatible stack locks while checking expected values,
   publish immutable tables before replacing the list, and retain explicit outcomes at every failure
   boundary. Cover contention with Git, conditional stale writers, interrupted table/list
   publication, cleanup and compaction preserving references and retained reflogs. Compaction must
   coordinate with writers and readers without discarding concurrent updates.
1. **Reference API integration:** Select the backend from repository configuration and retain the
   existing reference-domain entry points. Cover stored and resolved edits, all expected-value
   predicates, symbolic HEAD logging, no-log updates, ref/log deletion and namespace conflicts.
   Characterize linked-worktree common/private stacks and mixed-stack transactions before deciding
   their publication contract. Unsupported required behavior needs a named queued owner.
1. **Completion evidence:** Demonstrate Git-to-girt and girt-to-Git committed-tip, reference and
   reflog observations in both formats, including a nonempty repository. Add deterministic fault and
   race cases, representative Criterion stack/read/write/compaction measurements and separate
   resource observations. Run affected native suites on Ubuntu 22.04/24.04, macOS and Windows;
   retain exact executable revisions, run URLs, artifact fingerprints and failed attempts.

Each implementation stage remains separate until its relevant checks pass. Opening a repository
alone does not establish correct import: R14's unchanged jj baseline omitted the committed reftable
tip. Final consumer integration remains R35. C02 retains existing tracing, malformed-alternate and
platform owners. R40 retains imported files-reflog interpretation; R37 must state any distinct
binary-record representation limit explicitly. Pack performance work is outside R37.

## Integration Inventory

The current `References` API routes reads, enumeration, reflogs, conditional writes and prepared
transactions directly to the files backend. Repository opening rejects reftable. Integration must
include prepared transactions used by colocation, not only `References::transaction`, and must
preserve explicit partial effects when one operation spans different storage publication units.
