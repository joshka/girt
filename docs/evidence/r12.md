# R12 Index Versions, Flags and Extensions

R12 implements the full-index portion of
[A09](../jj-acceptance.md#a09--index-and-colocation-primitives). R13 owns colocation and
operation-state workflows. R38 owns split shared-index storage and sparse index directory handling;
these remain explicit refusals and are required before R34.

## Acceptance Scope

- Parse and encode full v2/v3/v4 indexes in SHA-1 and SHA-256, with checked v4 path decompression.
- Retain stat words, byte paths, conflict stages, executable modes and assume-valid; add
  intent-to-add and skip-worktree data without implementing consumer staging/sparse-checkout policy.
- Preserve unchanged encoded bytes, including nonmaximal v4 compression. Bound encoded bytes,
  decompressed path bytes, entry counts and extension counts; reject corrupt/truncated framing.
- Discard stale cache trees and other derived caches after edits, retain resolve-undo bytes, and
  refuse unknown optional extensions. Preserve the prior snapshot on failed edits.
- Compare both read and write directions with independently Git-generated fixtures. Observe split
  and sparse indexes and retain their explicit unsupported boundaries.
- Preserve old publication bytes and independent concurrent changes in both hashes and new versions.
- Run local formatting, full checks, public example, private Rustdoc, Criterion and focused native
  index tests on Linux, macOS and Windows; retain exact revisions and artifacts before acceptance.

## Public Surface

`index::Version`, `Index::version`, `Index::set_version` and `IndexEdit::set_version` expose
framing. `Entry::intent_to_add` and `Entry::skip_worktree` expose extended bits. `Index::new`
selects v3 for extended flags, otherwise v2; entry edits retain the version or upgrade v2 to v3.
Explicit v2 conversion rejects extended flags. Invalid conversion leaves the old index unchanged.

The owning modules are `index::codec`, `index::entries` and `index::store`. Raw status and checkout
explicitly refuse the newly accepted flags pending caller policy. `examples/index.rs` demonstrates
SHA-256 v4 publication. No dependencies or jj consumer code are changed.

`TREE`, `UNTR`, `FSMN`, `EOIE` and `IEOT` are derived caches discarded when entries or version
change. `REUC` is retained as prior conflict information. Unknown optional extensions block edits;
unknown mandatory extensions block parsing. Identical entry replacement retains original bytes and
every extension. Payload internals remain opaque. Index equality compares
format/version/entries/extensions, not alternate encodings. Original bytes are retained alongside
decoded records, so limits describe proportional bounds rather than an exact heap budget.

## Git and Boundary Observations

The [retained probe](r12-observations.json) uses installed Git 2.55.0 and unchanged jj 0.45.1 in
independent temporary repositories. Both SHA-1 and SHA-256 split fixtures open in jj and report a
clean working copy. Both sparse fixtures open, but jj reports the omitted `outside/b` file as
deleted. Opening therefore does not establish sparse workflow parity. R38 retains both capabilities
before R34, including interpretation of this baseline difference. The rerunnable original probe
script is retained with the logs.

`tests/index.rs` has 50 local cases: Git stat/debug observations, flags, all three framing versions,
stages 1/2/3, executable/symlink/gitlink modes, long and non-UTF-8 byte paths, stale cache-tree
removal, Git resolve-undo interpretation after editing, linked/separate directories, lock contention
and racy stat behavior. New flag-policy tests verify raw status/checkout refusal without index or
worktree mutation on macOS/Linux. Windows excludes those four traversal cases. Git creates split and
sparse fixtures in both formats; failed girt opening preserves their bytes and releases its lock.
Git's explicit sparse expansion produces a readable full index with retained skip-worktree flags.

Focused units cover malformed/truncated v4 prefixes, overflow, unknown extended bits, decompressed
path limits, nonmaximal compression preservation, known/unknown extension policy and transactional
version refusal. Existing storage faults cover read, write, timestamp/publication and cleanup
boundaries; additional v3/v4 both-format tests inject rename failure and an independent writer,
asserting exact old or concurrent bytes and lock cleanup. No crash-durability guarantee is added.
