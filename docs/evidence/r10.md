## APIs and Behavior

- `Repository::open` accepts relative linked backlinks and `extensions.relativeWorktrees`, preserves
  checkout inference through `.git` symlinks and OS aliases, and keeps private metadata openable
  when its checkout is unavailable. Common-directory requirements still fail independently. Direct
  bootstrap settings follow Git's shared/private worktreeConfig distinction; includes continue to
  affect only the effective config snapshot.
- `Repository::is_bare` distinguishes a bare repository from nonbare separate metadata whose
  checkout location is unknown. Direct metadata opening remains useful after checkout removal;
  checkout/status report the unknown location without guessing a root. Both-format installed jj
  observations confirm direct separate-metadata opening.
- `Repository::open_worktree` compares canonical common-directory identity and returns structured
  `OpenError::Unrelated` for another repository.
- `Repository::worktrees(max_entries, cancel)` returns sorted linked registrations, excluding the
  main repository. `Worktree` retains `git_dir`, optional backlink path and `WorktreeState`:
  available, missing, inaccessible with cause, or invalid with cause. A damaged entry does not hide
  other registrations. A checkout replaced by a file is invalid, not a missing common repository.
- `ShallowRoots`, `ShallowError`, `Repository::shallow_roots`, `refresh_shallow`, and
  `Objects::shallow_roots` provide immutable, format-aware boundary snapshots. New private modules
  are `repository/shallow.rs` and `repository/worktrees.rs`; public types remain root re-exports.
- History `walk`, `is_ancestor` and `merge_bases` stop parents only at declared boundaries. Raw
  object payloads and `Commit::parents()` are unchanged. Visited boundaries still require valid
  readable commits; unrelated missing parents remain `HistoryError::Missing`.
- `KnownHistory`, fetch workflow preparation/installation, and push preparation explicitly refuse
  shallow use. Installation also checks live shallow-file presence for a stale handle. No shallow
  request, negotiation, deepening or clone capability was introduced.

Shallow lines require full-width IDs. LF/CRLF, final unterminated records and duplicates are
accepted; duplicates coalesce. Blank/non-hex/wrong-width records report their line. Missing/null
root declarations remain metadata, without invented objects. Git 2.55.0 accepts an overlong SHA-1
record's valid prefix; girt deliberately requires the selected format's exact width, rather than
silently accepting SHA-256-looking bytes as SHA-1. Both-format observations are retained in
[r10-observations.log](r10-observations.log).

## Acceptance Evidence

The native environment is macOS 26.6.2 arm64, Apple M2 Max, Rust/Cargo 1.98.1 and Git 2.55.0. The
installed unchanged jj executable is 0.45.1. The temporary fixture volume provided case-insensitive
and Unicode-normalization aliases; both were executed, not inferred lexically.

The 38 new public layout/shallow cases cover both object formats: direct separate metadata and
unknown checkout locations, linked/private routing, absolute and relative backlinks, whole-layout
moves, checkout moves followed by Git repair, missing/inaccessible/invalid registrations, private
bootstrap and include behavior, unrelated repositories, directory/gitfile symlinks,
case/normalization aliases, shared shallow routing, depth-one clones, Git deepening/unshallowing,
old/new readers, graph boundaries, missing ancestors, null/missing/wrong-kind declarations, failed
refresh, and resource refusals. Linux-only byte-path cases are selected but were not executed on
this host. Existing `repositories`, `sha256`, `config_resolution`, `index` and reference suites
retain ordinary/bare/separate layout, initialization, discovery and private-state coverage.

Local shallow parser tests cover both formats, duplicates, malformed/wrong-width data, byte budgets,
cancellation and preservation. Public cancellation/entry budgets precede inventory results. Failed
refresh retains the old snapshot. The installation test proves a newly created shallow marker
prevents publication even through an older handle and leaves the object pack directory empty. A file
replacing a checkout remains unchanged after inspection. Optional tracing covers failure
classification, redaction, span closure and filtered-parent isolation, with no paths or IDs
recorded.

Fixtures use Git and explicit filesystem edits; the inspected girt operations are read-only. Depth
changes exercise atomic Git metadata replacement between reads. In-place concurrent edits and an
atomic snapshot spanning shallow metadata, packs, refs and loose objects are not promised. Callers
exclude concurrent depth changes while constructing/using a mutually consistent view and during
installation. Opening other metadata retains the trusted-filesystem contract; inventory and shallow
reads have explicit bounds and cooperative cancellation. Existing history calls remain synchronous
without cancellation.

The retained observation script additionally proves explicit-path jj initialization and reopening
still import the intended fixture when `GIT_DIR`, `GIT_COMMON_DIR`, `GIT_WORK_TREE`,
`GIT_OBJECT_DIRECTORY` or `GIT_SHALLOW_FILE` points at a nonexistent override. This establishes
those tested explicit-path workflows, not every jj command or environment variable. Consumer
call-site inspection covered `lib/src/git_backend.rs` open/reopen/shallow caching and
`lib/src/git.rs` worktree HEAD iteration; no API shape was copied. Their inspected SHA-256 file
fingerprints were respectively `528cea3e56a2e7c70ed8cb1de614bcffe2a230209cb5c7440be97754ebb3608a`
and `253733e3ba07b6a7efd2cc323969215bd335d08a5a10a0b8d1424fa9a7f31e06`.

`examples/repository_layout.rs` demonstrates paths, registration availability and shallow roots. It

Criterion baselines used the checked-in release profile and source above. The history/enumeration
run used 10 samples, one-second warmup and three-second measurement, with tracing disabled:

```sh
cargo bench --no-default-features --bench history --bench repositories -- \
  'history/|repository/worktrees' --sample-size 10 --warm-up-time 1 \
  --measurement-time 3 --save-baseline r10-complete
```

| Warm workload                               | 95% interval     |
| ------------------------------------------- | ---------------- |
| Linear packed walk, 256 commits             | 3.0128–3.0829 ms |
| Linear packed walk, boundary at commit 128  | 1.4685–1.5012 ms |
| Linear merge bases, 256 commits             | 3.0268–3.0751 ms |
| Merge-heavy packed walk, 256 commits        | 2.7762–2.8776 ms |
| Merge-heavy walk, declaration at commit 128 | 2.7982–2.8510 ms |
| Merge-heavy merge bases, 256 commits        | 2.7093–2.7761 ms |
| 10 registered worktrees                     | 2.2640–2.3147 ms |
| 100 registered worktrees                    | 22.902–23.156 ms |

The merge-heavy boundary's ancestors remain reachable through a sibling branch, so that declaration
does not halve the graph. [Full benchmark output](r10-bench.log) retains sampling and outliers.
Between-run and host noise preclude attributing small differences or comparing different operations
as an optimization claim.

The tracing harness used 30 samples, one-second warmup and two-second measurement:

[Disabled output](r10-tracing-disabled.log) and [enabled output](r10-tracing-enabled.log) retain

Fixture creation is outside measurement; cached filesystem reads are warm, not cold-storage claims.
