# C02 Storage and Layout Review

## Inspected Revisions and Decision

This task reviewed R20 executable `f8aaa936ab877243faf9c8a94d106e595fe06b75`, evidence child
`15acb57ad141`, and the accumulated R11–R20/R36–R40 contracts in the linked evidence reports. The
separate review change is `81321e9c`; the prune remedy is
`70a8f81f957d20db1776643d88f127971eac89a7`. R18/B01 remains a deferred draft. This was a scoped
contract and architecture review, not a new line-by-line audit of every previously accepted
implementation.

The coordinator accepts R20 repair and locks within their documented caller-exclusion, partial
effect and crash limits. The original prune predicate was unsafe as a general retention decision:
`tests/worktree_admin.rs` moved a live checkout and then pruned its registration, deleting its
private roots while the checkout still existed. The remedy requires the public caller to supply
`WorktreeRetirement::Confirmed` before removal. The caller must decide that the private HEAD, index,
refs and reflogs are disposable. Expiry, lock, absent-target, inaccessible-target and partial-I/O
behavior stay in place. A moved checkout retains its private metadata through repair; a separate
test confirms intentional pruning. Automatic move discovery and durable multi-file repair remain
[B02](../jj-roadmap.md#b02--automatic-worktree-move-and-crash-recovery). R31 still needs its own
complete root inventory before GC.

## Coherence and Compatibility

The reviewed public boundaries keep references/reflogs, index/colocation, object storage and
worktree metadata with their respective owners. R37/R38/R40 carry object format and backend choices
through public operations. R39 defines primary/alternate lookup and corrupt-duplicate behavior;
R15/R16 own file resource bounds, fixed snapshots and explicit refresh. Publication and repair
errors retain partial effects for caller inspection. No additional cross-module abstraction or
correctness blocker was established by this scoped review.

R39's [original observations](r39-observations.json) show Git continuing past some NUL, quoted-tail
and invalid-escape alternate records. Girt rejects those records explicitly. The unchanged jj
consumer inventory requires alternates but does not show a need to recover malformed records
produced by ordinary workflows. Keep strict rejection and reopen compatibility work if a required
consumer repository cannot be read. Permissive recovery must not silently choose a different object
store or weaken corrupt-duplicate handling.

R14's [consumer inventory](r14.md) found no production need for girt raw status or checkout. jj owns
working-file snapshot and materialization. Windows raw status/checkout refusal therefore does not
justify a new adapter before first integration. R35 must repeat the call-site check against its
target jj revision and promote a concrete required path if one appears.

## Native Windows ACL Denial

The final fixture at `75150864ed6e06f7ae2ca8540ae91f65be2fd114` uses the runner's numeric SID and
Windows
[`icacls`](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls)
on disposable worktree metadata. It removes each deny ACE before cleanup, including through a drop
guard after failed assertions. The
[four-host reference run](https://github.com/joshka/girt/actions/runs/36215849842) passes; its
Windows job executes eight worktree cases, including both ACL cases and scoped Clippy. The automatic
[broad platform run](https://github.com/joshka/girt/actions/runs/36215849812) passes all three Unix
jobs and fails Windows only at the previously recorded zero-`fetch.http` tracing assertion. It was
not retried. The focused worktree result establishes the ACL contract; the broad run remains failed
and B04 retains the tracing investigation.

Read denial on the checkout `.git` file is established by an actual `PermissionDenied` from
`fs::read`. Windows still returns file metadata under this ACL, so prune refuses the live target as
protected or uncertain rather than treating it as absent. Repair reports uncertainty when it cannot
read the forward link. Private HEAD, index, backlink and a private log remain unchanged. Write
denial on the registration is established by a failed `create_new` probe. On this runner,
registration canonicalization reports uncertainty before either operation obtains its private lock;
the fixture also accepts a permission-denied lock error on a platform that reaches that step. Both
outcomes refuse pruning and repair before modifying private metadata. Git can read the checkout's
symbolic HEAD after each deny ACE is removed.

Three earlier native revisions retain their failed fixture observations: the
[first](https://github.com/joshka/girt/actions/runs/36215226453) assumed read denial also denied
metadata inspection; the [second](https://github.com/joshka/girt/actions/runs/36215363232) compared
a verbatim Windows path with a lexical path; the
[third](https://github.com/joshka/girt/actions/runs/36215680985) expected a lock I/O error after
registration write denial, while canonicalization refused earlier. The final fixture requires actual
read/write denial and accepts only safe refusal outcomes. None of the failed attempts is called
passing safety evidence.

## Scoped Acceptance and Backlog

Native Windows ACL denial closes the remaining C02 safety evidence gate. The coordinator accepts the
scoped storage/layout and native worktree milestone under the roadmap's latency policy. The broad
platform matrix remains failed, and untested path forms have no parity claim. Pruning still requires
caller-confirmed retirement before private roots may be removed.

- **Compatibility backlog:** Revisit malformed-alternate recovery only when a required jj repository
  or generated metadata demonstrates the need. Retain the offending bytes and the intended store
  selection. Explicit rejection remains the current documented behavior.
- **Platform backlog:** UNC, drive-alias and WSL-relative-backlink fixtures need their respective
  native environments. Reopen when jj integration uses those path forms or an affected user workflow
  is identified. Ordinary native drive and Unix path evidence does not establish these cases.
- **Test reliability backlog:** Reproduce tracing and split-index failures with the diagnostic
  artifacts above. Reopen immediately if evidence shows an operation-lifetime or index correctness
  defect rather than fixture behavior.
- **Transport fixture follow-up:** Preserve the macOS read-before-wait deadline failure in the C03
  test owner. Separate its watchdog from the transport deadline or synchronize the EOF observation
  before asserting wait behavior; do not broaden C02's storage implementation for this fixture.

R41 remains after C02 and before transport. Its early A20 corpus covers normal capabilities that
already exist; later owners extend it. Optional malformed metadata recovery, unsupported raw Windows
workflows and unavailable topology fixtures do not become new performance prerequisites.
