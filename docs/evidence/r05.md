# R05 — SHA-256 Packs, References and Indexes

R05 propagates the repository object format through pack/index v2 storage, files references, reflogs
and working-tree index v2 under
[A02](../jj-acceptance.md#a02--object-format-and-identity-foundations) and
[A05](../jj-acceptance.md#a05--object-stores-resource-bounds-and-refresh). Its parent is R04
`85f492bf4283b7cea31e248d7eb2dc8353b3d496`. No jj consumer edits, publication or merge are included.

## Public API and Format Selection

- `write_pack(format, objects, pack, index, limits)` and
  `write_pack_with_compression(format, objects, pack, index, limits, compression)` require an
  explicit format even for empty exports. Mixed inputs fail before either sink is touched. Pack
  identities, index identity tables, REF_DELTA base IDs and both trailers use that format. CRC32
  remains unchanged. Ordinary and bounded internal REF_DELTA output retain ordering, duplicate,
  resource, partial-artifact and caller-owned publication contracts.
- `Repository::objects` reads SHA-1 and SHA-256 pack/index v2 pairs. Both checksums, fanout, CRCs,
  offset tables and boundaries are verified at opening. Reading verifies framing, zlib completion,
  base/intermediate/result identities, cycles and reconstruction budgets. OFS_DELTA distances are
  independent of hash width. Empty artifacts still have format-specific checksums.
- `index::Index::new(format, entries, limits)`, `Index::parse(format, bytes, limits)` and
  `Index::empty(format)` require a format. `Default` is removed; `object_format()` exposes the
  retained selection. `replace_entries` rejects foreign identities without changing the previous
  value. Canonical v2 padding, stat words, conflict stages and opaque extension representation keep
  their existing contracts. `Repository::read_index` and `edit_index` select the repository format,
  including an absent index. The obsolete `StorageError::UnsupportedFormat` variant is removed.
- `Repository::references` now supports both formats on its existing Unix backend. Loose and packed
  targets, peeled IDs, transaction targets and expected values must match the repository. All-zero
  direct targets remain rejected; reflog creation/deletion sentinels use the repository format.
  `ReflogEntry::parse(format, bytes)` also requires a format, including for empty input. Existing
  normalization of reflog timestamps/timezones and message-separator handling is unchanged.
- History, tree operations, status and checkout retain the store/repository format. Status hashes
  working bytes with that format and parses packed HEAD commits accordingly; checkout checks target
  and baseline IDs against the repository before locking.

No artifact chooses its format from plausible length, filenames or embedded identities. Repository
configuration or the explicit argument selects it. Pack/index headers themselves do not identify it.
Every `.idx` basename remains an accepted publication marker, including noncanonical names; matching
contents establish integrity, not the basename. Unindexed packs remain ignored, while a missing pair
fails opening. Indexed snapshots survive later removal of the original files.

The shared incremental checksum helper is private. No new public type/module or dependency is added.
All local callers are migrated directly, including empty constructors and SHA-1-only protocol paths.
The public writing examples `index`, `reference_transaction` and `write_pack` demonstrate SHA-256.

## Interoperability and Failure Evidence

Fixtures are original and generated in disposable repositories with inherited Git overrides and
system/global configuration disabled. Only Git's executable and published
[pack](https://git-scm.com/docs/gitformat-pack) and
[index](https://git-scm.com/docs/gitformat-index) specifications informed this work. No upstream
implementation or test source was used.

- `tests/packs.rs` reads Git-created SHA-1/SHA-256 ordinary objects and actual OFS/REF deltas,
  comparing blobs, trees, commits and tags to `cat-file`. Girt exports ordinary/delta packs,
  including empty, binary and large payloads. Git `index-pack` independently generates
  byte-identical v2 indexes; `verify-pack` checks the generated pair and selected delta depths.
- The internal received-pack validator accepts explicit formats. Its independent Git fixtures
  contain real OFS/REF deltas in both formats; reconstructed bytes agree with Git and Git
  regenerates the identical index. Units cover forward references, missing/cyclic bases, duplicate
  identities, malformed zlib/programs/offsets, empty transfers, wrong-format/truncated/checksum
  failures, cancellation and exact/exhausted decode/depth/resolution budgets. This is storage
  validation, not SHA-256 protocol negotiation or a new public raw-pack installation API.
- Pack units cover both-format corrupt headers/checksums/CRCs, fanout, offset tables, duplicate or
  unsorted IDs, missing bases, long chains, truncation and identity verification at each delta step.
  Index integer reads now reject overflowing offsets explicitly. Writer tests preserve empty-output
  prevalidation, complete-pack/partial-index outcomes, flush failures, cancellation and trailer
  accounting. Snapshot tests retain corrupt-loose precedence, missing pairs, ignored unindexed
  packs, bounds and retained reads after repack.
- `tests/references.rs` compares Git and girt reads/updates, loose-over-packed shadowing, exact
  packed deletion retention, symbolic resolution, conditional writer races and transaction reflogs
  in both formats. The transaction unit fault matrix runs in both formats: preparation errors,
  foreign locks, packed-first partial deletion, later-ref failure, failed/partial log appends and
  lock ownership retain their structured outcomes. Pure reflog tests cover empty/null and foreign
  IDs.
- `tests/index.rs` observes Git stat words, assume-valid flags, conflict stages, byte/long paths,
  `ls-files`, `write-tree`, exact unedited bytes, linked/separate layouts and lock races in both
  formats. Index storage fault tests cover failed writes/renames, foreign or replaced locks,
  noncooperating writers, cleanup, corrupt reads and output bounds in both formats. Codec tests
  cover truncation, wrong formats/checksums, null entries, retained opaque extensions and atomic
  rejection of mixed replacements. Null index IDs are data, not a promise of valid object targets.
- `tests/sha256.rs` exercises packed history through checkout and HEAD-based status, independently
  checking `ls-files`, `write-tree`, `diff` and strict `fsck`. A dirty file remains unchanged after
  a refused checkout. Foreign-format on-disk refs/indexes and operation IDs fail without
  publication; corrupt index edits release their acquired lock and preserve original bytes.
- Tracing retains subscriber ownership and safe fields. SHA-256 index/loose success, foreign-object
  refusal and SHA-1 transfer installation refusal retain completion/failure classifications without
  sensitive sentinels or events. Import spans record only the closed format alongside existing
  counts. Format support does not add cancellation to synchronous snapshot/index/ref reads.

No rollback, fsync guarantee, atomic multi-ref visibility, hostile-path defense or platform support
is inferred beyond the existing contracts. Failures after publication still require callers to
inspect structured outcomes before retrying. Boundary tests are finite evidence, not universal Git
parity or process-wide memory/latency guarantees.

## Remaining Owners

- **R06:** Execute and retain the native Linux/Windows matrix for R04/R05. Existing portable
  selections now cover both-format pack/index suites, while Unix refs and macOS/Linux
  checkout/status remain scoped. Windows also runs the SHA-256 index and pack-writing examples.
  Cross-compilation does not establish runtime behavior.
- **R11:** Portable files refs, broader reflog identity/date acceptance, resource ceilings and
  reference semantics. Preserve both-format zero IDs and partial outcomes while characterizing
  signed dates and other Git-readable records; do not equate this increment with full refs parity.
- **R12:** Index v3/v4, extended flags, split/sparse indexes and extension/cache policy.
  Characterize zero-checksum input and Git's checksum-skipping configuration explicitly. Retain
  unrelated bytes and reject unsafe edits before replacement in both formats.
- **R14–R16:** Characterize pack v3/index v1, alternates and external/thin bases; then file-backed
  bounded reads, refresh and concurrent publication. Current snapshot bytes remain eagerly owned,
  missing same-pack REF_DELTA bases fail, and MIDX/reverse/bitmap indexes are not used. Tests of
  small synthetic offsets are not multi-gigabyte native-file or cold-cache measurements.
- **R26/R29:** SHA-256 transport advertisement/negotiation and fetch/push. SHA-1 protocol encoding,
  local knowledge and installation guards remain; even an empty SHA-1 transfer cannot install into a
  SHA-256 destination. Storage support cannot authorize protocol format changes.
