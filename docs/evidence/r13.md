# R13 Colocation Primitives

## Acceptance Criteria

- Compose locked index replacement with conditional stored HEAD edits for detached, symbolic and
  unborn HEAD in SHA-1 and SHA-256 repositories. Preserve unrelated branches and working files.
- Reuse cached stat data only for matching path, stage, mode, identity and extended flags; caller
  drafts retain staging and sparse policy. Invalidate cache trees through existing index edits.
- Inspect bounded recognized operation metadata in the worktree Git directory. Clean only inspected
  metadata, reject changed snapshots before deletion, and report exact partial removals and causes.
- Exercise independent Git merge/cherry-pick/rebase metadata, malformed filesystem nodes, resource
  limits, concurrent changes and cleanup faults. Preserve unrelated metadata and worktree files.
- Preserve R12 index publication fault guarantees and test composed HEAD/index partial outcomes.
- Run local checks and native portable evidence on all four existing workflow hosts. Record exact
  revisions and limitations; R38 owns split/sparse storage, R37 reftable, and R14 characterization.

## Implementation and Consumer Boundary

The executable revision is `80badf1619f239df9c76efad067746fa22e3dc03`. The evidence child changes
only documentation, including a private comment clarifying inspection order. The unchanged jj
checkout remains `be5f5ebdc200593d8f1be06f11e27b485a97093d`. No dependency or jj source changes were
made.

- `Repository::edit_colocation` returns `ColocationEdit`; `index_mut` exposes the held index draft,
  `abort` reports index-lock cleanup, and `commit` prepares a conditional stored HEAD edit before
  publishing index then HEAD. Reference locks remain held across both publications.
  `ColocationError` distinguishes preparation (including index-lock cleanup failure), index failure,
  and HEAD failure after index publication. Nested `TransactionError` retains reference/reflog
  effects. Existing reference preparation/publication is reused through crate-private entry points.
- `IndexEdit::replace_entries_reusing_stat` matches path, stage, ID, mode and all flags against the
  current locked draft. Matching entries inherit cached stat words; others retain caller-supplied
  values. Existing validation, extension invalidation and racy-stat publication rules remain active.
- `Repository::operation_state`, `OperationLimits` and `OperationState` supply bounded opaque
  metadata inspection, root enumeration and file-byte access. `cleanup` verifies the complete
  snapshot before removing individual files and empty directories. `OperationError` distinguishes
  I/O, unsupported nodes, bounds and changed state. `OperationCleanupError` retains exact completed
  removals and cause. Implementations live in `src/repository/colocation.rs` and
  `src/repository/operation.rs`; their types are re-exported at the crate root.

Intent-to-add and skip-worktree are caller-controlled data in these primitives, including stat reuse
and Git-readable publication. jj chooses added placeholders, merged-tree/conflict staging, reset
ordering and materialization. Colocation does not call raw status/checkout, so its flagged-index
support does not depend on their existing refusals. R14 explicitly retains assessment of any other
consumer requiring raw flagged-entry workflows and must queue bounded work before R34 if needed.
This resolves the R12 boundary for these colocation primitives without asserting wider raw-workflow
parity. R38 retains split/sparse storage and R37 reftable.

## Compatibility and Fault Evidence

Disposable repositories and operation states are generated through Git's public CLI, with isolated
configuration and signing disabled. No upstream implementation or test source supplies fixtures. The
corpus exercises detached/symbolic/unborn HEAD, unchanged former branches and working files, HEAD
conflicts before index publication, observed noncooperating index replacement, extended flags, Git
stat reuse and linked-worktree private routing. Git independently reads published indexes and HEAD
with `ls-files`, `diff`, `symbolic-ref`, `rev-parse` and `fsck` where applicable.

Conflicting Git merge, cherry-pick, merge-backend rebase, apply-backend rebase and multi-revert
sequencer operations supply real metadata. Cleanup preserves HEAD, the conflicted index, working
files and unrelated roots. Independent `git merge/cherry-pick/rebase --quit` cases establish primary
marker removal without index reset; girt's generic metadata discard is not full command emulation.

Ten operation units cover exact removals, simultaneous roots, changed/new roots and children,
byte/node/depth bounds, invalid root types, injected partial deletion and Unix nested symlinks. Four
both-format colocation units force HEAD rename failure after index publication and reflog failure
after both index and HEAD publication. Eight stat-reuse units independently vary every matching
field. R12's unchanged storage-fault corpus continues to cover descriptor-write, encoding,
timestamp, rename and owned-lock failures. Tracing integration covers hierarchy, completion,
changed-state failure, filtering and sensitive-data exclusion. Disabled tracing uses the same
structured outcomes.

## Recovery and Remaining Limits

Index/HEAD publication is ordered, not atomic. HEAD failure after index publication must be
recovered from the returned per-reference/reflog effects; no rollback is attempted. Cooperating
index and reference writers honor existing lock protocols. Noncooperating writes after final
comparisons, metadata-directory replacement and crash durability remain outside those protocols.

Operation metadata has no shared Git lock. Callers must exclude operation writers for inspection and
cleanup; byte/presence rechecks cannot prevent a later race or detect ABA replacement. Cleanup is
metadata discard, not command abort, working-file restoration or complete bisect reset. BISECT_LOG
is a recognized consumer cleanup artifact; other bisect state is preserved. Unknown external roots,
ORIG_HEAD, refs/logs and worktree files are not recursively swept. C02 retains Windows raw
status/checkout assessment and UNC/WSL/ACL/lifecycle evidence. R14 retains subsequent
characterization and any required broader consumer operation policy.
