# R38 Split and Sparse Index Evidence

R38 is in progress. R37 coordinator acceptance is the separate parent documentation change
`187760310e7d29835df20747b400efb226f88d9c`; its executable and native evidence remain unchanged.

## Acceptance Contract

Resolve SHA-1 and SHA-256 split indexes through public index and colocation operations, including
shared-file checksums, replacement/deletion bitmaps, additions, versions and entry flags. Preserve
unchanged storage bytes; deliberately publish a standalone full index after entry or version edits.
Never modify or collect the immutable shared file. Bound aggregate main/shared input bytes and
resolved entries. Recheck both original files before publication and preserve old main-index bytes
on failure. Missing shared files require restoration; retry only after inspecting changed state.

Preserve sparse directory records and their tree identities without materializing files. Supply
explicit bounded tree expansion that retains skip-worktree policy and canonical leaf modes. Cover
missing, corrupt and wrong-kind trees, cancellation, depth, entry, byte and path limits. Sparse
storage changes must compose through colocation while leaving staging and materialization to the
caller. Successful initialization and refusal are not compatibility evidence.

Use original Git-created fixtures in both formats and independent binary boundary cases. Sources are
the published [index format](https://git-scm.com/docs/index-format) and
[EWAH format](https://git-scm.com/docs/bitmap-format); no upstream implementation or test source is
used. Required completion includes local checks, scoped native Linux/macOS/Windows execution,
publication race/fault cases, measurements and exact executable/artifact identities. R40 remains
next, then R17. R19/R20, R31/R32, R35 and existing C02 owners retain their established scope.

## Split Storage Stage

`Index::parse_with_shared` resolves explicit shared bytes; `Index::shared_index_id` identifies the
preserved dependency. Repository reads and locked edits resolve files automatically. The private
`index::split` module owns bitmap decoding and overlay resolution. `StorageError::MissingShared`
distinguishes an absent dependency. Colocation uses the same guard. No dependency is added.

Original Git CLI tests cover both-format replacements, deletions, additions, assume-valid flags,
unchanged exact-byte publication, full v4 conversion, missing/corrupt dependencies and dependency
removal during a held edit. Independent bitmap tests cover runs, literals, truncation, excessive
positions, run pointers and padding. Native evidence and sparse implementation remain outstanding.
