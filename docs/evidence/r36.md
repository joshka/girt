# R36 Windows Native Integration Coverage

R36 inventories supported operations against
[A16](../jj-acceptance.md#a16--native-ci-and-platform-coverage), repairs the nine R08/R10 Windows
failures, and extends the existing platform workflow. C02 retains its broader storage/layout
milestone; native execution of selected cases does not establish full Windows or jj parity.

## Acceptance Criteria

- Preserve R12 acceptance as a separate documentation change above its evidence child.
- Establish Git's home-condition semantics before changing the condition matcher or its fixture.
- Rerun all nine known failures natively without disabling cases or weakening discovery assertions.
- Inventory every integration suite and distinguish omitted portable tests from unsupported
  operations, platform-specific fixtures, and future capability work.
- Execute the expanded Windows selection and applicable Linux/macOS suites, retaining exact
  revisions, logs, toolchains and filesystems.
- Keep unresolved exclusions and substantive follow-ups explicitly owned; update the roadmap and
  callback without dispatching a successor.

## Condition Semantics and Discovery

[Git's configuration specification](https://git-scm.com/docs/git-config#_conditional_includes)
defines `~/` expansion and trailing-slash recursive matching. The original fixture compares
`gitdir:~/repo/` with a canonical home and Git directory. On Windows, joining the suffix to a
verbatim `PathBuf` normalizes the path and drops its trailing separator. Girt then matches the
repository directory exactly instead of matching its `.git` descendant. The matcher now appends
condition bytes to the expanded home without sending glob syntax through filesystem path joining.
Include-file path expansion is unchanged.

The Git-comparison fixture checks the independent Git result before asserting girt's result.
Additional cases cover a home wildcard, an exact `.git` match and absence of recursive matching
without the trailing slash. Four unit cases exercise these same local matching boundaries without
Git. These changes preserve the expected meaning; the home case is not reclassified as a fixture
failure.

The eight discovery failures compared Git's slash-separated output bytes to Rust's canonical
verbatim/backslash spelling. They now canonicalize the Git output and compare paths, preserving
both-format discovery, ceiling and non-mutation assertions. A Unicode repository name with a
space-bearing child also compares Git with ordinary and canonical paths; on Windows the latter is a
verbatim drive path. UNC shares, WSL and denied-access ACL fixtures remain C02 evidence gaps.

## Portable Coverage and Exclusions

The canonical [suite inventory](../testing.md#native-platform-coverage) accounts for each
integration suite. No new CI matrix is added. The existing broad Windows job gains `references` and
`http`, while the R11 and R12 focused workflows remain available for ref/index faults and
both-format interoperability.

Reference enumeration and fetch-planning units no longer have whole-module Unix gates. Enumeration
symlink fixtures retain individual Unix gates. Clone completion/failure units build an in-memory
pack response instead of spawning the unsupported local adapter; their existing publication,
residual-object, cancellation and lock-failure assertions run on all hosts. Reference and clone
tracing cases likewise use the supported portable paths. No public API or dependency changes.

The `references` suite runs both formats, including loose/packed/symbolic routing, worktree/private
refs, imported/appended logs and concurrent Git writers. Its non-UTF-8 argv fixture remains
Unix-only and its raw filename fixture remains Linux-only. Packed non-UTF-8 names are separately
unit-tested without requiring those filesystem/argv capabilities.

The HTTP suite exercises SHA-1 negotiation, TLS trust and hostname checks, authentication, limits,
truncation, cancellation, partial/uncertain outcomes, ref publication and clone completion. The
shell-hook fixture remains Unix-only. SHA-256 transport negotiation remains unsupported and owned by
R26/R29; SHA-256 storage success or rejection tests are not transport parity evidence.

`fetch`, `push`, `fetch_workflow` and `clone` retain their local-process integration fixtures. The
Windows local adapter is unsupported; R25 owns native transport and R24 owns SSH lifecycle support.
R27/R28/R30 own the broader negotiated-transfer, publication and cancellation corpus as those
capabilities arrive. Portable planning/completion units and HTTP workflows now execute separately,
so the fixture exclusion does not suppress those operations entirely.

Raw status and checkout remain unsupported on Windows. Their portable suites test cancellation and
explicit refusal only. C02 must assess the consumer requirement and assign any required native
traversal/materialization implementation before R34; a green refusal test cannot close that gap.
R19/R20 retain worktree administration, ACL/registration and repair coverage; C02 retains native
UNC/drive/WSL and denied-access evidence. R31–R33 retain maintenance, R37 reftable and R38
split/sparse index storage. No network-filesystem or crash-durability guarantee is added.

## Validation

The final local `just check` passes on macOS arm64: 1,578 all-feature units, 1,016 integration
cases, 20 doctests, formatting, all-target Clippy and warning-denying docs.rs. Core-only units pass
1,548 cases. Focused config/layout/reference and HTTP runs also pass. Markdownlint, rumdl and
actionlint pass. Native results remain pending; no pending or failed attempt is counted as passing
evidence. Performance benchmarking is inapplicable: this change preserves a configuration glob
suffix and broadens test execution without introducing a significant processing path or a
performance claim.
