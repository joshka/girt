# R30 Push Outcome Evidence

R30 extends the [R29 command contract](r29.md) without changing exact-old leases, graph selection or
pack contents. A failed first write is `NotSent`. Per-command `attempted` flags distinguish later
packets never written from commands that may have reached the peer; missing acknowledgements for
attempted commands remain uncertain. A complete rejection is a report result, not a transport error.
Neither wire nor owned transports retry a mutation automatically.

## Response and Progress

Receive-pack uses `report-status-v2` when advertised, including v2-only servers. The parser keeps
the server's byte-preserving rejection text and records proc-receive `refname`, `old-oid`, `new-oid`
and `forced-update` options for each successful pseudo-ref. An `ok` packet is retained when later
framing fails, while `rewrite_complete` remains false until the option block ends. Callers can
report that acknowledgement but must inspect the remote before treating a missing rewrite as a known
destination. Duplicate, malformed, unrequested and contradictory status data fail explicitly. These
rules follow Git's
[pack protocol](https://git-scm.com/docs/pack-protocol#_report_status).

`PreparedPush::with_progress` requests `side-band-64k` when available. Channel-2 frames are bounded
by `max_status_bytes` and retained as untrusted bytes in the report; channel-3 failure is an
uncertain remote error. Partial status and progress survive a truncated sideband response. Generic
blocking streams still require caller-provided interruption for blocked I/O. Owned HTTP, SSH and
local-server transfers retain their existing cancellation, deadline and process cleanup rules. HTTP
starts uncertainty at the mutating POST; SSH and local-server adapters distinguish no successful
request write from a possible server mutation. No progress callback is promised during an in-flight
HTTP or SSH exchange: C03 should review the transport boundary, and R35 must confirm whether jj
needs live delivery rather than the bounded report. Any required expansion must precede final
replacement.

## Native Receive Policy and Reflogs

Native local push supports current-branch refusal, ignore and warn for updates, and
`receive.denyDeleteCurrent` for deletions. Warned successful updates carry a diagnostic in
`PushReport::warnings`. Ordered `transfer.hideRefs` and `receive.hideRefs` patterns reject only
matching commands, with `!` exceptions. Existing `receive.denyDeletes` and
`receive.denyNonFastForwards` checks remain per-ref. These modes follow Git's
[receive configuration](https://git-scm.com/docs/git-config#Documentation/git-config.txt-receivedenyCurrentBranch)
and
[hidden-reference rules](https://git-scm.com/docs/git-config#Documentation/git-config.txt-transferhideRefs).
Invalid receive boolean values refuse before object installation rather than disabling a
restriction.

`send_local_with_identity` makes the reflog identity explicit. `core.logAllRefUpdates` controls
automatic creation, existing logs append even when creation is disabled, and deletion removes the
edited ref's log. A missing or invalid required identity refuses before object installation.
Reference transaction outcomes are returned separately from log outcomes after publication failure;
a published ref with a failed append is not reported as an intact log. The files backend checks log
existence without loading complete history. Reftable uses its bounded snapshot.

The native adapter does not execute hooks, proc-receive or `updateInstead`; configured use refuses
before mutation. It also refuses push options, fsck/input-size receive settings and shallow
destinations. R35 must compare these local-policy exclusions with actual jj call sites. A required
mode needs a dedicated implementation and validation before final replacement. Namespace rewriting
outside the repository's opened configuration is not covered. Server-side external effects,
including hooks on wire transports, cannot be rolled back by the client.

## Validation

Focused tests cover first-write failure, a short upload that leaves a later command unattempted,
malformed and truncated v1/v2 reports, v2 rewrites, sideband channel separation and truncated
sideband prefixes, current-branch update/delete modes, warn diagnostics, hidden-ref exceptions,
invalid receive policy values, both-format reflog creation/deletion, and Git's reading of
native-pushed objects and reflogs. A Git receive-pack push independently rejects the configured
hidden ref. Existing HTTP, SSH, local-server and portable suites cover mixed ref success/rejection,
remote hooks, cancellation, deadlines and child cleanup. Real Git HTTP and SSH initial pushes now
request sideband progress; synthetic v2 packets exercise proc-receive option interpretation. An
original Python proc-receive hook on Git's HTTP receive-pack rewrites `refs/for/main` to
`refs/heads/reviewed`; girt reports the alternate name, new ID and forced flag, and Git resolves the
published alternate ref. This executable fixture is SHA-1 on Unix; C03 should extend it to other
applicable transports and formats if the jj target server needs them.

The [push baseline](../benchmarks.md#push-baseline) and
[native-local baseline](r25.md#local-evidence) remain the performance references. V2/sideband
reencodes only the bounded command request; pack buffers are borrowed by SSH and moved by HTTP,
without a new whole-pack copy. No new throughput ratio is claimed.
