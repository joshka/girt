## Findings and Acceptance Evidence

### F1: Shallow records

Only the shallow decoder takes the selected-width prefix. SHA-1 records with 64 hexadecimal digits
use the first 40; SHA-256 uses 64. Trailing text, NUL and non-UTF-8 bytes are uninterpreted
suffixes. Short/nonhex prefixes and blank records still return one-based `InvalidRoot` errors.
Existing coalescing, read budgets, cancellation and failed-refresh preservation remain covered.

`tests/layout_shallow.rs` adds 20 both-format Git comparisons: LF, CRLF, no final newline, hex,
text, NUL and binary suffixes, plus short/nonhex prefixes and an extra blank record. Accepted cases
compare `git rev-list --parents HEAD` with public history traversal and verify raw commit parents
and shallow bytes remain unchanged. [Focused log](c01-f1.log).

The unchanged external [18-observation probe](c01-probe.json) separately confirms prefix acceptance
and parent suppression. Its invalid/overlong commit-parent controls still fail in Git and girt even
at a declared boundary. The original snapshot binary, driven with freshly generated two-commit
repositories, preserves `old=2 refreshed=1`, failed-refresh state, and `unshallow=2 retained=1` in
[both formats](c01-snapshot.json).

### F2: Discovery candidates

Explicit `.git` entries remain candidates. Bare recognition requires `HEAD`, `objects` and `refs`;
linked metadata requires `HEAD` and `commondir`. Lone names and partial bare signatures allow
ancestor search. Recognized malformed/unsupported or inaccessible candidates still fail, preserving
structured errors. Initialization retains its original conservative marker check before writes.

Twelve both-format integration cases cover ordinary HEAD/objects names, inclusive ceilings,
initialization refusal with no `.git` creation, partial bare fallback, genuine nested bare metadata,
malformed recognized HEAD and denied-access nested `.git`. Existing unit cases cover ordinary nested
repositories, malformed explicit gitfiles, dangling symlinks, physical ancestry and empty read-only
searches. The [focused log](c01-f2.log) predates the two permission cases; the full check includes
them. The original external [four observations](c01-discover-probe.json) now find the outer
repository exactly as Git does. Partial-bare fallback is also compared with Git; malformed
recognized candidates deliberately retain the documented error policy rather than silently falling
back.

### F3: Configuration comments

The preliminary file-wide NUL scan is removed. Existing lexical name, subsection, escape and value
checks continue rejecting NUL in interpreted syntax; comment scanning skips inert bytes through the
physical newline. `Config` and `Document` share that parser. Newly supplied values, environment
pairs and path interpretation retain their own checks.

Eight both-format integration cases compare Git before and after parsing, repository bootstrap,
resolution, lossless `Document` editing and held-lock publication. They retain exact NUL bytes in
trailing, standalone, header and CRLF comments and read the following assignment. Seven new
rejection cases exercise NUL in quoted values, keys, section/subsection names, escapes, between
assignments and quoted comment markers. [Core units and config-edit log](c01-f3.log).

Independent [config observations](c01-config-probe.json) and
[additional observations](c01-more-config.json) now accept both inert-comment reproductions and
preserve their bytes during edits. NUL-containing values remain rejected: the original Git display
observation does not establish their internal semantics. R21 owns that separate characterization;
this does not defer or disguise F3's required comment compatibility.

### D2: Tracing

`config.resolve` now uses the documented owning-operation target and initial outcome. An exact
`girt`/DEBUG subscriber sees it with only `outcome = "incomplete"` initially, then `success`.
Existing cycle-failure/redaction and filtered-parent tests continue passing. The capture records
initial fields before completion so the test cannot pass solely from the final outcome.
[Three focused regressions](c01-tracing.log) and all tracing suites pass in the full check.
