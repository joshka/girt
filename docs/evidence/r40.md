## Acceptance Contract and Public API

`References::imported_reflog` reads one named history with `ReflogLimits` and cooperative
cancellation. `ImportedReflog::read` applies the files reader to caller-owned `Read` inputs. Both
hash formats and both reference backends expose the same owned report, records, interpreted fields,
completion test and recoverable-root iterator. Existing strict `ReflogEntry`/`ReflogRecord` and
signed `reflog` reads remain available with their documented limits; canonical `Reflog::Append`
validation is unchanged. No dependency is added. The new private `refs::imported` module owns record
interpretation and bounded reading; reftable routing and append-boundary checks stay with their
existing owners.

`ImportedRecord::File` preserves every retained byte, including CR, NUL, non-UTF-8 data and
incomplete prefixes. `ImportedRecord::Reftable` preserves the update index and exact decoded
`LogValue`, including its full unsigned timestamp and message bytes. Compressed table representation
remains codec-owned. `fields()` returns borrowed `ReflogFields`: i128 seconds include the entire
binary u64 range, names exclude files delimiter padding, and messages exclude one storage LF on
either backend. It does not construct or validate a canonical append. Four signed HHMM digits are
interpreted arithmetically; suffix bytes become message data after removing one optional tab. Short
zones and dates beyond i128 remain explicit interpretation failures, with raw bytes and recoverable
IDs intact.

`ReflogReadEnd` distinguishes EOF, limits, cancellation and I/O. EOF can still contain corrupt or
unterminated records. `is_complete()` requires EOF and successful interpretation of every retained
record. `recoverable_roots()` recovers each fixed-position nonzero old/new ID independently,
including when its peer, identity, date or tail is malformed. Candidates retain duplicates; object
existence, kind and inter-record continuity are not checked. No arbitrary message hex is treated as
an ID. Incomplete reports and opening/stack errors must block destructive GC decisions, not become
empty root sets. Retain candidates and repair/retry or defer collection.

R31 retains discovery across deleted names and worktrees, retention/expiry policy and
repository-wide coordination. A complete live read of one name is not a GC snapshot. R32/R33 retain
maintenance execution, R35 final consumer parity, and existing C02 platform/tracing/alternate owners
are unchanged. The unchanged jj inventory from R14 remains applicable; no jj source is modified.

## Exact Git Operations and Fixture Provenance

Original fixtures use Git's executable, independent byte mutations and the girt binary codec. No
Git, gix or libgit2 implementation/test source is used. `tests/imported_reflogs.rs` and
`tests/fixtures/reflogs/observe.py` retain generators. The latter records 130 both-format operation
observations, including the exact original R11/R14 short-zone, suffix, overflow, CR/NUL and tail
spellings. Each observation names its command, HEAD mode, input and output bytes.

`git reflog show --format=%H %gn %gs HEAD` falls back to the untouched branch reflog for the
short-zone and unterminated fixtures when HEAD is symbolic. The same command with detached HEAD
emits no record for those fixtures, including ten-digit timestamps. R11's apparent acceptance
therefore did not establish parsing of the modified HEAD file. CR is displayed, suffix text appears
in the message, and the overflow-date record is displayed. For `a<NUL>b` and `x<NUL>y`, `%gs` is
empty on the measured Git version; girt preserves all bytes. These are display observations, not
universal grammar rules. The probe separately records `git rev-list --reflog --all`; the live branch
still points at the same commit, so its output is not evidence that each malformed log independently
retained that commit.

`git update-ref --no-deref -m append HEAD <distinct-tip>` appends directly after an unterminated
tail, preserving its prefix without inserting a delimiter. An unchanged detached tip can skip the
write; the corrected fixture creates a distinct commit and asserts the appended old/new ID prefix.
Girt continues to refuse a nonempty unterminated tail before publication so the new record cannot be
hidden inside an earlier message. The caller must inspect/repair explicitly. Terminated unusual or
malformed old lines no longer block canonical appends: preparation checks only the final byte under
the existing lock instead of reading and interpreting the whole file. Canonical NUL/CR/LF messages
remain rejected on both backends. Both-format colocation composes with unusual retained history.

## Resource and Failure Bounds

Files reads request at most 8 KiB per chunk and retain bounded raw records. Defaults are 64 MiB
total input and retained payload, 2 MiB per record and 100,000 records; callers select their own
budgets. Budgets include partial prefixes. No extra byte is read past a byte budget just to prove
EOF, so an exact-budget file reports a limit. Record/count stops can read ahead within the bounded
chunk; there is no continuation token or promise about reusing the reader position. Vector capacity,
allocator overhead and record structs are additional proportional costs, not exact RSS bounds.
Cancellation is checked between chunks and while consuming bytes; blocking I/O is not interruptible.

Reftable first uses the existing bounded whole-stack snapshot, with configurable aggregate encoded,
decoded, record, string and table budgets. Selected-log budgets then bound returned decoded payload
and records. Snapshots and output can coexist. Cancellation is checked at snapshot boundaries and
between records; one bounded table decode can finish first. Tombstones and stack precedence are
resolved before history is returned. Corrupt/missing tables and stack limits return errors rather
than partial authoritative roots. Binary output limits can retain only earlier records; completion
remains false. Broader streaming table decoding is not claimed.

Tests cover per-file/record/retained/count bounds, exact byte boundaries, zero budgets,
pre-cancelled reads, cancellation during a long record, invalid IDs, i128 overflow, unterminated
tails, 1 MiB messages and 10,000-record logs. Injected `Read` failure retains complete records and
the next partial prefix. Directory/path failures and corrupt/missing/over-budget binary stacks fail
explicitly. Both-format worktree tests distinguish private HEAD and shared branch history. Existing
transaction write/rename/partial-append and lock/race tests remain applicable and run in scoped
native validation. Publication remains non-durable, with the existing
trusted-directory/cooperating-writer assumptions; arbitrary external changes after tail checking are
outside the exclusion guarantee.
