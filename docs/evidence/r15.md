# R15 File-Backed Object Storage

R15 is in progress against
[A05](../jj-acceptance.md#a05--object-stores-resource-bounds-and-refresh). R39 coordinator
acceptance is recorded in parent change `86a2df6c`.

## Acceptance Contract

- Read primary and alternate repositories beyond the former 512 MiB whole-pack budget without
  retaining pack bytes in RAM. Preserve SHA-1/SHA-256, pack v2/v3 and index v1/v2 support.
- Preserve REF/OFS reconstruction, long-chain limits, identity checks, corruption and missing-base
  distinctions. Compare original runtime fixtures with Git; reuse unaffected import-format evidence.
- Bound aggregate validation bytes, index input and derived memory, descriptors and directory work.
  Bound per-read compressed and decoded work. Demonstrate limit failures and cleanup.
- Provide cooperative cancellation for opening and reads with explicit blocking-I/O and checkpoint
  contracts. Exercise cancellation and path-preserving I/O errors through public APIs.
- Retain reproducible Criterion open/lookup/decode observations, memory and descriptor measurements,
  and cold/warm workload descriptions without claiming a portable cold-cache guarantee.
- Run affected storage checks natively on Linux, macOS and Windows. Retain exact tested revisions
  and failed attempts alongside successful checks.

## Boundary with R16

R15 pins open pack/index file handles. Shared immutable pack state uses `Arc`; seek/read cursor
access is serialized per artifact without descriptor duplication. Files must remain immutable while
readers use them. Unlinking or renaming an open artifact follows platform semantics. This is not an
atomic pair/topology snapshot, does not protect against in-place writes, and does not provide
refresh. R16 owns publication races, external repack/GC policy, refresh, retry and retained-reader
consistency contracts. Loose reads remain live; no negative or decoded-object cache is introduced.

## Resource Policy

The default aggregate artifact-validation budget is 64 GiB on 64-bit hosts, index input is 64 MiB,
file handles are 512, pairs are 256 and pack-directory entries are 1,000,000. All stores share these
budgets. Each pair pins two descriptors; opening rejects excess rather than evicting and reopening
potentially replaced paths. Pack validation uses a 64 KiB buffer. Index IDs are read from the pinned
index by binary search; bounded entry ranges and offset-order tables remain in memory. Opening
temporarily parses one index, with input and derived allocations bounded conservatively by four
times aggregate index bytes, excluding allocator overhead and paths.

Packed reads use a 64 KiB input buffer and 8 KiB output scratch; they retain only pending delta
programs and reconstructed payloads under existing decode bounds. Compressed ranges additionally
charge a default 256 MiB per-read work budget before inflation. No cross-read cache is retained.
Caller-owned returned payloads and concurrent calls multiply memory use; this is not a process RSS
quota. Loose compressed input retains its prior output-bound policy.

Cancellation checkpoints surround alternate discovery and index parsing, occur between directory
entries and lookups, every 64 KiB of pack validation, every inflate chunk, and between delta
applications. Individual OS calls, bounded index parsing/sorting, object hashing and delta
application are synchronous and finish before the next checkpoint. Callers needing executor
responsiveness must run whole operations on bounded blocking workers and join before reclaiming
resources.

## Implementation and Initial Validation

New public calls are `Repository::objects_controlled`, `Objects::read_controlled` and
`Objects::clone`. `PackLimits` adds index-byte, descriptor and directory-entry budgets; `ReadLimits`
adds compressed-input accounting. `ObjectReadError::Cancelled` is a distinct outcome. The private
`pack::file` module owns pinned artifacts and file-backed identity lookup. Existing reconstruction
logic is shared with the in-memory test reader. No dependency or license changes occur.

The original decoder corpus now exercises file-backed reads, including missing REF bases, invalid
OFS boundaries, cycles, long chains, rejected zlib streams and resource limits. Public tests compare
all four object kinds, both formats, REF/OFS deltas and legacy versions with Git. New cases cover
exact budgets, aggregate alternate budgets, cancellation/retry, cloned concurrent readers, CRC and
checksum failures, and short reads of pinned artifacts. Unaffected import/reference/index evidence
remains applicable; the complete local suite also exercises their integration with this reader.

The [pack specification](https://git-scm.com/docs/gitformat-pack) supplies format facts.
[Original generator](../../tests/fixtures/file-storage/generate.py) asks Git 2.55.0 to create
18-object SHA-1/SHA-256 stores, each with 17 uncompressed 32 MiB blobs and one small blob. Pack
sizes are 570,469,211 and 570,469,223 bytes, respectively. The generator uses bounded chunks and
runs separately from reader measurements. No upstream implementation or test source was consulted.

Initial local `just check` found a fixture that increased pack count to 257 without increasing the
new descriptor budget; it now explicitly permits 514 handles. Earlier new truncation fixtures
exposed canonical-path assertions on macOS and Git's read-only index permissions. The fixtures now
canonicalize expected paths and recreate writable artifacts before pinning. The first unit compile
also required a default for the new read-limit field. All failed attempts are retained. Subsequent
`just check` passes 1,632 units, all integrations, 20 doctests, Clippy and docs.rs. Native
validation and final benchmark/resource observations will be recorded in the evidence child.
