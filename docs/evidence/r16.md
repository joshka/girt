## Acceptance Contract

- Refresh primary and alternate pack/topology views explicitly; retain Arc-shared old readers.
- Leave the old view intact on cancellation, corruption, missing pairs or exhausted budgets.
- Distinguish immutable pinned artifacts from live loose paths, directory replacement and
  unsupported in-place mutation. Preserve shallow boundaries.
- Make one bounded attempt per refresh; expose errors and explicit recovery without hidden retries.
- Exercise publication after misses, interrupted pairs, pair-open interleavings, changed alternates,
  external Git repack/GC, concurrent loose writers and resource cleanup on native hosts.
- Record exact executable revisions, scoped native results, resource observations and limitations.

## Implementation and Compatibility

New public calls are `Objects::refresh` and `Objects::refresh_controlled`. They reopen and validate
all pairs before replacing the current stores. No dependency or new public type is added.
`objects.rs` owns the operation; `pack::file` adds a private deterministic checkpoint between index
and pack opening for race tests. The no-op production checkpoint does not change validation.
[Compatibility contracts](../compatibility.md#r16-object-store-refresh) and `Objects` Rustdoc own
retention, consistency, retry, cancellation and aggregate resource policy.

`tests/refresh.rs` uses original runtime Git-generated SHA-1/SHA-256 fixtures from
`tests/support/pack_git.rs`. Git `cat-file`, `gc --prune=now` and `prune --expire=now` independently
observe payloads and live loose deletion. Direct filesystem staging deterministically exercises
publication markers and missing/corrupt pairs; no timing race is used as proof. File-pair unit cases
interleave removal, valid-but-mismatched pack replacement and index-path replacement between the two
opens. Existing import, pack codec, alternate parsing and R15 large-store evidence is reused. No
upstream implementation or test source is consulted.

`tests/fetch.rs` additionally exercises refresh after actual `ReceivedFetch::install` through the
existing Unix local transport. SHA-256 transport remains unsupported; both storage formats are
covered independently. Existing R15 malformed-artifact/short-read and R39 topology evidence remains
applicable. C02 retains malformed-alternate policy, platform path/ACL and tracing owners.

## Resource and Performance Observations

Local measurements use Rust 1.98.1, Git 2.55.0 and macOS 26.6.2 arm64. Local reports are retained
under [/Users/joshka/.codex/reports/girt-r16](/Users/joshka/.codex/reports/girt-r16). The R15
original 18-object fixtures retain 570,469,211-byte SHA-1 and 570,469,223-byte SHA-256 packs.
Running the updated `storage_resources` probe in separate processes on macOS arm64 reports handles 4
before open, 6 after open, 6 after clone, 8 after refreshing while retaining the clone, and 4 after
dropping both generations. Failed refresh returns to the prior count. Whole-process maximum resident
bytes are 2,211,840 for SHA-1 and 2,244,608 for SHA-256 small-object reads. Windows measurements
remain unclaimed. These few-object fixtures do not establish many-object index RSS behavior.

`cargo bench --bench packs -- 'packs/refresh-warm'` measures full refresh of original Git-created
16/256-blob stores (plus three metadata objects), with 30 Criterion samples. Median estimates are
133.50 microseconds (95% interval 131.44–140.79) and 567.99 microseconds (511.05–630.63). Filesystem
cache is warm. Concurrent local builds and a separate benchmark overlapped; these observations are
not an isolated regression comparison or a speedup claim. Retained estimate JSON and source
fingerprints identify the workload. R15 opening/decode observations remain historical baselines;
refresh performs the same full validation work while retaining the previous generation.
