# R25 Native Local Transport Evidence

R25 replaces the local Git upload-pack and receive-pack process adapters with girt repository,
object, pack and reference operations. The local entry points accept an explicit trusted repository
path. `Destination::local_path` converts an R21-resolved local or `file://` destination to that
path; it does not execute a program. Fetch returns a validated pack for separate installation. Push
installs a prepared pack, then applies individual conditional reference transactions.

## Endpoint and Helper Inventory

[Git fetch URL documentation](https://git-scm.com/docs/git-fetch#_git_urls) identifies absolute and
relative local paths, `file:///` URLs, scp-like SSH, standard network schemes, and explicit
`transport::address` remote helpers. [Git clone documentation](https://git-scm.com/docs/git-clone)
distinguishes a local path's clone optimization from a `file://` URL. Girt accepts ordinary local OS
paths, including relative paths and Windows drive/UNC syntax, and absolute `file://` URLs with empty
or `localhost` authority. It decodes percent escapes once and refuses malformed escapes, NUL, and
remote file authorities. Local transport is opened through `Repository::open`, which resolves the
repository layout and handles OS paths. No shell or local Git service is involved.

R21 recognizes unknown `scheme://` destinations as helpers; R25 also recognizes explicit
`scheme::address` destinations. R25 exposes their exact scheme and applies `protocol.<scheme>.allow`
or `GIT_ALLOW_PROTOCOL` before any caller dispatch. Recognition and protocol permission alone do not
authorize a helper executable. The
[remote-helper protocol](https://git-scm.com/docs/gitremote-helpers) offers `connect` for smart Git
streams and `import`/`export` or `push` for other systems. The inspected jj Git subprocess and URL
call sites do not select a required custom helper protocol or approved executable. Therefore R25
starts none. A consumer that needs a helper must supply an explicit approved executable and protocol
contract; a helper that runs local Git upload-pack or receive-pack cannot close a required local
endpoint. Reopen `connect` when a required named endpoint uses it, with a synthetic approved
process, capability/fallback refusal, cancellation and platform tests. Reopen import/export or
helper-owned push only for a concrete required endpoint and object/ref translation contract.

## Native Contract

- Fetch lists girt refs, resolves HEAD and symbolic refs, emits tag peel hints, checks selected IDs
  against the advertisement, and reads a bounded complete graph from loose or packed objects. It
  writes a pack/index in memory in the repository format. Verified known history can reduce that
  pack; installation rechecks excluded dependencies. Empty, missing, corrupt, wrong-kind,
  interrupted, shallow and resource-limited cases fail without destination effects.
- Push preparation validates the complete source graph, force policy and expected values before
  mutation. `PreparedPush::new_local` supports SHA-1 and SHA-256. Native send preflights all current
  refs and verified receiver roots, installs objects, then uses one conditional transaction per
  destination. Known preparation failures reject that ref; publication failures and interruption
  after installation retain an uncertain report. No automatic retry occurs.
- Native push refuses existing receive hooks or configured hook paths before publication. It refuses
  updates to checked-out branches in the main or registered linked worktrees and honors a
  conservative `receive.denyNonFastForwards` setting. It does not run hooks, append reflogs or
  implement the broader server policy and push options owned by R29–R30. Callers must coordinate
  concurrent worktree registration, configuration changes and GC. Object installation may leave
  complete unreachable packs after a later ref rejection; pack publication is no-clobber.
- Both object formats and files/reftable reference backends are exercised. Wire HTTP/SSH/stream
  fetch and push remain SHA-1-only until R26–R30. Native local transfer does not turn on those
  protocol features.

## Local Evidence

The new `tests/local_native.rs` creates original source commits with girt, transfers them across
both formats and both reference backends, and asks the Git executable to read each destination's
commit. It checks conditional push refs and a missing source object. Existing fetch, clone, fetch
workflow and push suites exercise packed Git-generated inputs, object kinds, advertised tag peels,
incremental transfer, empty repositories, stale refs, force rules, mixed outcomes and interrupted
operations. Hook fixtures now assert refusal without executing their synthetic programs. Protocol
stream and owned-process tests remain separate. Endpoint units cover `file://` decoding, helper
syntax/policy and refusal. No production Git service is invoked by `receive_local` or `send_local`.

The local macOS focused suites and format/backend matrix pass at the R25 working revision.
`just check` passes formatting, all-feature tests, all-target Clippy and docs.rs; the native
examples still need the origin workflow. Exact validation revision and native CI links will be
recorded after publication. No dependency was added.

Criterion 0.8 measured warm-cache native transfer at code revision
`f7449c682b38c73f605f98c0102864080c6413a0` on macOS 26.6.2 arm64, Rust 1.98.1 and Git 2.55.0. Run
`cargo bench --locked --bench fetch -- native-local-read-pack --noplot` and
`cargo bench --locked --bench push -- native-local-publish --noplot`. The fetch path lists source
refs, reads the complete reachable graph and constructs a pack, excluding installation. Push
receives a prepared pack and installs it into a fresh bare repository, then publishes one tag;
repository initialization is outside the measured operation. Sources are warm packed fixtures with
19 or 259 objects and approximately 0.55 or 8.8 MiB of uncompressed payload. Each case has 30
Criterion samples. Retained [sample and estimate files](../benchmarks/r25-native-local/) contain the
raw observations and confidence intervals.

| Operation                    | 19 objects, median | 259 objects, median |
| ---------------------------- | ------------------ | ------------------- |
| Native fetch read and pack   | 2.692 ms           | 36.124 ms           |
| Native push install and refs | 12.520 ms          | 12.289 ms           |

The older Git-server baseline includes different work and fixtures; these measurements establish no
Git throughput ratio. Warm filesystem caches, fsync latency and concurrent desktop activity can
affect times. The push measurements are dominated by fresh pack/index publication and one ref
transaction; they do not include preparation.

## Remaining Gates

Native Windows runtime validation and origin CI remain required before acceptance. Native local
policy intentionally differs from Git receive-pack for hooks, reflogs and some configuration;
R29–R30 own the broader push model, and R35 must assess actual jj integration impact. R26–R30 own
negotiation, fetch and push expansions. A custom helper becomes required only when a concrete
consumer endpoint identifies its scheme, executable, trust policy and protocol.
