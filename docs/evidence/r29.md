# R29 Push Command Evidence

R29 extends conditional push commands across full `refs/` names in SHA-1 and SHA-256 repositories.
The `PushCommand.new` field uses the format-specific null ID for deletion and requires a nonzero
exact old ID for that operation. Creation requires absence; updates retain the caller's exact old
ID. The wire receiver checks each old ID under its reference transaction, so one stale command can
reject while another succeeds. Girt neither retries nor turns a stale lease into an unconditional
update.

## Wire and Native Scope

`PreparedPush::new` and `new_excluding` prepare either format. V0 receive-pack advertises the object
format; SHA-256 requests `object-format=sha256`. Deletions require `delete-refs`; caller-supplied
byte-preserving options require `push-options`. Missing capabilities fail before transmission.
Options reject NUL and newline bytes and share the bounded command byte budget. Push preparation
still validates complete selected graphs and builds a non-thin pack. Deletion-only pushes send no
pack. No wire or native adapter executes a Git client subprocess.

Native local push applies each ref through a conditional girt transaction after installing objects.
It supports mixed commands, both formats, checked-out branch refusal, `receive.denyDeletes` and
`receive.denyNonFastForwards` with an ancestry proof for forced branch replacements. It refuses
configured receive hooks, hidden-ref/proc-receive/input-size/fsck policies and push options before
mutation. The local adapter does not append reflogs; [R30](../jj-roadmap.md#push-follow-through)
owns explicit identity/log policy and the remaining configured receive modes. Object installation
can persist when a later ref rejects. Reference publication and interruption can retain partial
effects; inspect destination state before a new attempt.

The existing [R25 native-local push baseline](r25.md#local-evidence) remains the measured
install/reference path. R29 does not change graph selection or pack encoding for non-deleting
commands. HTTP moves request and pack buffers into the POST; SSH borrows them. Options extend only
the bounded request buffer, and no transport clones the prepared pack. No new throughput ratio is
claimed for mixed-command workloads.

## Compatibility and Boundaries

Original Git repositories provide SHA-1 and SHA-256 commits, trees, tags and refs. HTTP tests push
`refs/for/main`, mix create/delete commands, send deletion-only requests, exercise stale leases with
an independent accepted ref, and verify push-option capability refusal and acceptance by Git. Unix
SSH tests create and delete the same arbitrary namespace in both formats. Native local tests cover
mixed create/delete commands in both formats, and Git reads the resulting objects. Synthetic wire
cases cover deletion capability mismatch with zero command bytes sent and option byte validation.
Existing push suites retain malformed/truncated report, cancellation, policy rejection and
uncertain-outcome coverage.

Native local does not run hooks or emulate all Git receive policy and reflog effects. Protocol v2,
shallow push, signed push, atomic push, progress sideband and report-status-v2/proc-receive rewrites
remain outside R29. R30 owns the response, progress, cancellation, local policy and reflog work
listed in the roadmap; R35 must assess required consumer endpoints and differences. The R25
native-local depth limit, Windows SSH exclusion, B07 fetch negotiation and R28 v2/filter exclusions
remain unchanged.

## Validation

The code was tested on macOS arm64 with Rust 1.98.1 and Git 2.55.0. The exact tested revision,
validation commands and native platform run will be recorded after publication. No dependency or
object-format storage change was needed. This is scoped interoperability evidence, not exhaustive
server-policy parity.
