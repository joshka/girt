# R21 Transport Configuration Resolution

R21 adds pure destination selection, a single prefix rewrite, and protocol policy to the existing
byte-preserving `Remote` snapshot. No transport is opened by these APIs. URL and environment bytes
remain explicit inputs, and `Destination` hides its bytes from `Debug`; callers can inspect them
only through `bytes()` and must keep them out of logs. The resolver refuses NUL-containing endpoints
and empty rewrite matches before any command or network operation.

The R41 scoped acceptance is revision `658d818e` on top of the published R41 stack at `e9f69f92`.
The R21 implementation and initial evidence are revision `fdeeb29e`; this completion note is a
separate follow-up change. The implementation is owned by `src/remote/endpoint.rs`, with the shared
boolean decoder in `src/config/values.rs` and callers in `src/repository.rs` and
`src/config/sources.rs`.

## Inventory and Boundary

The consumer treats local paths, `file://`, scp syntax, `ssh://`, HTTP(S), `git://`, and custom
schemes as possible inputs. The current girt transports execute only explicitly constructed HTTP(S)
and SSH endpoints on supported platforms. R25 owns native local/file and helper execution; R22 owns
credential and askpass lifecycle; R23 owns HTTP trust, proxy, redirect and authentication settings;
R24 owns SSH command, agent, key and host policy. Recognition in R21 does not promise that an
endpoint can already be executed. No production local Git executable fallback was added.

`remote.<name>.url` keeps its first remaining value for fetch. `pushurl` overrides all `url` values
for push; absent `pushurl`, push uses every remaining `url` in order. Empty occurrences reset their
respective lists. The longest `url.*.insteadOf` prefix rewrites fetch and explicit push URLs. On
push fallback from `url`, a matching `pushInsteadOf` wins; otherwise `insteadOf` applies. Equal
length matches use the first configuration occurrence. Rewriting is one pass, so replacement text is
not interpreted again.

The effective protocol policy follows `GIT_ALLOW_PROTOCOL` when explicitly supplied. Otherwise
`protocol.<name>.allow` overrides `protocol.allow`. The recognized safe network protocols default to
`always`, local/file default to `user`, and unknown helper schemes default to `never` pending R25.
`GIT_PROTOCOL_FROM_USER` is supplied as a parsed boolean, not read from process state. The API
returns refusal before transport execution and never interpolates configured values into errors.

Git 2.55.0 observations in a disposable repository: with `remote.r.url=short:long/repo`,
`url.ssh://host/a/.insteadOf=short:` and `url.ssh://host/b/.insteadOf=short:long`,
`git remote get-url r` returned `ssh://host/b//repo`. With `url.ssh://host/p/.pushInsteadOf=short:`
and the longer ordinary rewrite, `git remote get-url --push r` returned `ssh://host/p/long/repo`. A
separate `protocol.file.allow=never` `ls-remote file:///nonexistent` refused the transport before
path access. Original synthetic fixtures in `src/remote/endpoint.rs` exercise the same precedence,
local-path refusal, allow-list override, and diagnostic redaction.

## Limits and Follow-Up

Transport-specific parsing and canonicalization remain with R23–R25. In particular, this API does
not interpret credentials, percent encoding, IPv6 authority, scp port rules, local path expansion,
custom helper names, or command trust. An unknown scheme is recognized as a helper family but
refused by default. R25 must replace that coarse classification with exact helper protocol identity
and test the external-helper trust boundary before executing one. R21 does not claim complete Git
URL syntax or protocol-policy parity; R34 must assess that alongside integrated jj behavior.

The earlier C01 D3 debt is resolved by one configuration boolean decoder shared by repository
bootstrap and environment file selection. Source-specific error messages remain at those callers.
NUL-containing configuration value and path semantics still need an interpreting Git operation
before their rejection policy changes; retaining the current refusal is conservative, and R34 must
reopen it if a consumer needs those values.
