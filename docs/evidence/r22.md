# R22 Credential Lifecycle Evidence

R22 provides `remote::CredentialSession` for ordered credential-helper lookup and successful-use
approval or rejection. `remote::askpass` runs one approved askpass command. The application supplies
a parsed `CredentialContext`, maps configured helper names to approved executables, chooses whether
to prompt, and retains the secret until it knows the authentication outcome. R23 and R24 will
connect this lifecycle to HTTP and SSH.

## Behavior and Trust

The session reads ordered `credential.helper` values from a resolved `Config`. An empty value clears
previous helpers. URL-scoped credential sections match the supplied protocol, host and repository
path at a component boundary. `credential.username` seeds the username; `credential.useHttpPath`
controls whether the path is sent to helpers. Helpers receive Git's newline-separated `get`,
`store`, and `erase` protocol. Returned username and password fields are merged in helper order.
Nonzero helper exits are retained with their configured positions while later helpers run; a Git
2.55.0 `credential fill` observation with a failing first helper and a succeeding second helper
confirmed that ordering. `quit=true` stops lookup. Prompting missing fields is an explicit
application callback. Askpass is an explicit executable and literal argument list; it does not
discover `GIT_ASKPASS`, `SSH_ASKPASS`, or a terminal.

Configured values are never interpreted as shell snippets or executable paths by girt. The
application must approve and map each remaining helper name. A helper that shells out to local Git,
including unverified Git Credential Manager installations, is not silently made usable by girt; that
helper needs a dedicated compatibility test and an explicit application decision. Both helper and
askpass programs are trusted external commands, with access to local files. The application chooses
whether each program inherits the process environment and can supply explicit variables.

The process owner captures bounded stdout, discards stderr, polls cancellation and deadlines, and
reaps the direct child. On Unix it starts a process group and kills that group when the operation
ends. Windows uses native `Command` spawning and direct-child termination; descendant containment
requires a Windows job-object follow-up. Error displays and debug output omit credentials, URLs,
process output and executable paths. `CredentialError` retains an I/O source or a typed protocol,
exit, cancellation or deadline stage. Callback execution and process creation are synchronous and
cannot be forcibly interrupted. Run these APIs on an application worker when responsiveness matters.

## Validation and Limits

On macOS, the full `cargo test --all-features` suite passed. Focused synthetic shell helpers
exercise lookup, store, erase, helper reset, URL/path scope, configured username and path policy,
prompt fallback, askpass, nonzero exit continuation, `quit=true`, redaction, and deadline cleanup.
`just fmt-check`, `just clippy`, and `just docs-rs` passed after the final code edits. A native
Windows `.cmd` helper and askpass fixtures are exercised only on Windows. No live secret, keychain
or remote server is used. This evidence does not establish HTTP or SSH authentication, nor
compatibility with every installed helper. R23/R24 own transport integration and C03 owns native
Windows validation. Git's full URL matching, helper `state`/`continue` extensions, helper-specific
quoting, and Windows descendant containment remain follow-ups if consumer behavior requires them.
