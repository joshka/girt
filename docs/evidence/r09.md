## Public Surface and Ownership

`config::Document` retains source bytes and parser-derived header/assignment/value spans. The parser
uses one implementation with optional layout collection; ordinary `Config::parse` does not allocate
layout vectors. Document occurrence edits, append, section rename/remove preserve unrelated syntax,
comments, line endings, byte values, unknown keys and repeated ordering. New syntax uses quoted
values and LF. Removal leaves surrounding whitespace/comments. Implicit booleans can become explicit
values; BOM, deprecated dotted subsections and continuation ranges use the existing parser rules.

`config::ConfigEdit` owns a synchronous exclusive lock from read through commit/abort/drop.
`Repository::edit_config` selects the common local file; `ConfigEdit::open` selects another explicit
OS path. Source byte/presence checks distinguish missing and empty files and detect stale observed
state. `require_source` validates earlier snapshots. Commit publishes through same-directory rename;
`EditError` retains parse/precondition/limit/I/O failures and combined cleanup causes. Unix source
permission bits survive replacement. Drop cleanup is best effort; explicit abort reports failures.

`remote::RemoteConfig`, `RemoteKey` and `RemoteEditError` own transactional draft preparation for
add, append/set/remove URL/refspec occurrence, rename and local remove. URLs remain opaque bytes;
refspec mutations use direction-specific validation. Rename adjusts local branch selectors,
`remote.pushDefault`, and fetch destinations under the old remote namespace. Push refspecs and
custom fetch destinations remain exact. Remove clears matching local branch selectors and merge
entries while retaining unrelated settings. Repeated scalar selectors referencing the target fail
before changes; explicit occurrence editing resolves the ambiguity.

The file/effective distinction is explicit: no include/global target is rewritten, inherited-only
remotes return `NotLocal`, and local removal can leave a remote effective. Reopen with the original
inputs before constructing a fresh `Remote`; existing repository/remote snapshots do not change. The
[contract](../configuration.md#lossless-file-editing) and `examples/edit_config.rs` teach
lock/edit/commit/refresh and residual-lock recovery.

## Independent Git and Failure Evidence

All fixtures are original, generated in disposable directories using Git 2.55.0 as an executable
oracle. No upstream implementation, upstream test source or copyright-audit comparisons were used.
`tests/config_edit.rs` compares Git add/set-url/rename/remove with girt output and then has Git read
girt-published bytes. Cases cover SHA-1/SHA-256, repeated fetch/push/URL values, reset/fallback,
branch remote/pushRemote/merge and remote.pushDefault, custom refspecs, inherited-only/mixed
remotes, unchanged include/global files, stale consumers, deprecated syntax, escaped/non-UTF-8
subsections and values, BOM, continuations, CRLF, comments and exact unrelated text.

Observed practical boundaries: Git refuses unqualified set-url with multiple URLs, so tests use an
explicit old-URL selector and the library exposes occurrence selection. Git rename warns about
custom fetch destinations and leaves them unchanged. Repeated branch scalar selectors can make Git
warn and retain stale values; girt refuses preparation. Git independently preserved source mode 0600
during config replacement. macOS rejects arbitrary non-UTF-8 filenames; the arbitrary-byte filename
case is Linux-only, while Unicode paths run portably.

Focused units cover invalid edit preservation, empty/missing files, byte budgets, contention, stale
snapshots, noncooperating source creation/change/deletion, malformed syntax, write-descriptor and
rename faults, injected cleanup failure, combined primary/cleanup causes, foreign/replaced locks,
symlink destinations, restrictive permissions and abort/drop cleanup. An integration case
coordinates competing threads. Tracing tests verify parent hierarchy, nested abort, precondition
classification, closure, filtered-child isolation and absence of sensitive sentinels/events.

## Validation and Limits

On macOS arm64, Rust/Cargo 1.98.1 and Git 2.55.0, `RUST_TEST_THREADS=4 just check` passed 1,535 unit
tests, 895 integration cases and 20 doctests, nightly formatting, rumdl, Clippy across all targets
and features, and docs.rs with warnings denied. The [full log](r09-check.log) retains results. R09
contributes 32 focused units, ten macOS public-API cases (one additional Linux-only filename case),
and two tracing cases. The feature-disabled public suite and executable example passed;
warning-denying all-feature private Rustdoc built successfully. Linux and Windows core libraries
cross-compiled; the [portable/doc log](r09-portable.log) retains commands and results. Markdown lint
passed at 100 columns with the repository's explicit table-length exception; the source manifest
verified unchanged.

A default-parallelism full run hit the pre-existing push after-commit deadline test's missing hook
marker while cross-builds ran concurrently. Both deadline cases then passed in isolation and the
complete four-thread check passed. The [failure and recheck](r09-deadline-recheck.log) are retained;
no unrelated push code or test was changed. Scheduler contention is a possible cause, not a proven
root cause.

The [source manifest](r09-source.sha256) covers parser/editor/remote modules, fixtures, example,
manifest/lockfile and portable CI selection; verify with
`shasum -a 256 -c docs/evidence/r09-source.sha256`.

No benchmark was added: small configuration edits deliberately reparse prepared drafts, no material
hot path is introduced, and no performance claim is made. Large bulk edit optimization is outside
this increment. Linux/Windows native execution remains pending; portable selection is updated for
R36/C02. Cross-compilation, where recorded, is not runtime evidence.

Cooperating writers must honor locks. A noncooperating write after the final comparison cannot be
excluded; hostile directory replacement is outside the contract. Unix inode checks detect observed
lock replacement; other platforms require external exclusion of lock replacement. No fsync,
crash-durability, whole-operation atomicity, ownership/ACL/xattr copying or shared-repository
permissions policy is claimed. Browser security policy blocked local HTML preview, so visual Rustdoc
inspection is unavailable; warning-denying builds remain recorded independently.

R11 owns conditional references; R28 owns composition with remote-tracking ref rename/removal and
explicit cross-file inherited-setting edits, including partial outcomes. R35 owns consumer naming,
selection and view updates. Those follow-through requirements are queued in the roadmap; R09
configuration operations never pretend to mutate those other stores.
