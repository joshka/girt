# R19 Linked Worktree Creation

## Scope and Implementation

Executable revision: `37b21cc0292227155d480af5e2cc77a63fc8bdf2`. Its parent contains the R18
deferral documentation; R18 scoring and pairing are not prerequisites for this change. The R10–R13
prerequisites are accepted. No dependency or jj consumer source changed.

`Repository::create_orphan_worktree` in `src/repository/worktree_create.rs` creates an absent
checkout directory and private registration with `HEAD`, an empty v2 index, `commondir`, and a
backlink. Files and reftable use their respective private HEAD representations. It preserves
SHA-1/SHA-256 format, native filesystem paths and the common repository's direct
`extensions.relativeWorktrees` policy. The caller owns ordinary checkout and jj workspace metadata.
Public error variants distinguish preflight refusal, resource/format failures, filesystem partial
effects and post-write opening failure; a reserved registration remains available to inspect.

Git's public CLI permits two worktrees to point at the same unborn branch. The API preserves that
behavior and refuses a branch once it has a stored value. A destination filename supplies the
registration name and numeric suffixes resolve collisions within a caller bound. Existing checkouts
and invalid line-based link paths are refused before registration.

## Compatibility and Failure Evidence

`tests/worktree_create.rs` has ten native macOS cases at the executable revision. Six cases combine
both object formats and reference backends, including relative-path configurations. Git
independently reads the new private HEAD/index with `symbolic-ref`, `ls-files` and `status`, then
creates a commit and passes `fsck --no-reflogs`. The main HEAD stays unchanged. Additional cases
cover shared unborn HEAD, registration-name collision, a stored branch after the first commit, zero
name budget, invalid branch and line-break path refusal.

A Unix permission failure after metadata registration and before checkout directory creation retains
a registration with a readable private HEAD. Inventory reports the absent checkout as missing; the
error returns the failed path and registration. This exercises a recoverable leftover without
silently deleting metadata. A Linux-only native-byte path case runs in the same portable suite on
Linux. R20 owns repair, stale locks, expiry/pruning, concurrent repair/prune and final cleanup
policy. Creation currently requires caller exclusion from competing worktree administration; it does
not claim crash durability or safe concurrent path replacement.

## Validation and D4 Inventory Cost

On macOS arm64 with Rust 1.98.1 and Git 2.55.0, the final focused suite passed 10 cases.
`just fmt-check`, all-feature/all-target `just clippy`, warning-denying `just docs-rs`, and
`markdownlint-cli2 --config ~/.markdownlint-cli2.yaml docs/compatibility.md` passed. `just check`
passed all runtime suites and doctests before the final Git-observed shared-unborn correction, then
stopped at a Clippy `let_and_return` diagnostic. After that correction, the focused suite and
all-target Clippy passed. The full runtime suite was not repeated because unrelated test behavior
was unchanged. The first Windows run exposed Git's rejection of verbatim absolute gitfile paths. The
corrected code writes ordinary Windows link spellings and boxes the opening error to satisfy Windows
Clippy. A Windows-only unit checks disk and UNC spellings; the final focused suite, macOS all-target
Clippy and Windows GNU target library Clippy passed. Native Linux/Windows results are recorded
below.

The existing R10 inventory benchmark uses warm registered worktrees and calls
`Repository::worktrees`. Adding a 1,000-registration fixture to the same workload yielded 95%
intervals of 2.0795–2.2462 ms (10), 20.849–21.684 ms (100) and 216.51–220.54 ms (1,000) on this
macOS host with ten Criterion samples, one-second warmup and three-second measurement. The original
R10 100-registration interval was 22.902–23.156 ms. This is a scale characterization, not an
optimization claim: `Worktree::inspect` opens each linked repository and thus rereads common
configuration and shallow metadata for each registration. R19 creation avoids that inventory path;
R20 retains the coherent layout-inspection follow-through for repair/prune. No shared mutable cache
or repository context was added. Source fingerprints are
`97797d4c193a3eddb479501305f3c6aaed1438294ce9c269771b169e2b1ea1ed` for `benches/repositories.rs` and
`05de492821dc99e0739d2e6d63310c6956c26fcb31c52115c3acb733ac8e4b48` for
`src/repository/worktrees.rs`.

## Native CI

The scoped bookmark `joshka/r19-native-validation` publishes the executable revision. The existing
reference workflow now selects `worktree_create` on its four native hosts, including Clippy. The
broad workflow selects it explicitly in portable core cases; its Unix all-feature sweep discovers
the integration target. The origin push started the existing reference, index and platform workflows
automatically. No duplicate manual matrix was dispatched. Initial revision
`49e7ad2d14cb4b8d705f6e3fb7f8232fe1e95819` passed the three Unix reference jobs but failed Windows
Git interoperability: Git treated Rust's verbatim absolute gitfile link as nonlocal. Windows Clippy
rejected an oversized error variant. The corrected revision strips the verbatim prefix only when
serializing Git metadata. Initial failures do not establish corrected behavior.

The [corrected reference matrix](https://github.com/joshka/girt/actions/runs/36212130019) passed all
four hosts. The focused worktree suite passed 11 cases on Ubuntu 22.04 and 24.04 (including the
Linux native-byte path), 10 on macOS 14, and 8 on Windows Server 2022. Scoped Clippy passed on each
host. The [corrected index matrix](https://github.com/joshka/girt/actions/runs/36212129938) also
passed all four hosts. The
[broad platform run](https://github.com/joshka/girt/actions/runs/36212130047) passed both Ubuntu
hosts on attempt 1. Its macOS job initially failed an existing split-index test, and Windows
initially failed an existing tracing test. Only those failed jobs were rerun; both passed attempt 2.
The corrected executable revision therefore has passing reference, index and broad platform matrices
on all four native hosts. No merge, release or successor task was performed here.
