# R35 Bounded Unix Integration Attempt

## Status and Target

### Current Local Milestone

The local jj stack now uses released girt 0.1.5 for bounded native operations behind the default-off
`git.native-local-operations` setting. Plain HTTP fetch and push admit ordinary hosts, follow one
same-origin initial discovery redirect, and forward available sideband messages. HTTP push accepts
configured push-option defaults and explicit overrides. An uncertain push is reported without
retrying through Git. Live progress, HTTPS trust parity and ordinary SSH policy still require
consumer work and retain fallback.

Native worktree creation and repair now include first-use relative-link configuration promotion; the
symlink cases retain fallback. Worktree registration pruning deliberately stays with Git, preserving
cleanup and path reuse while R35-W1 remains open. The native index milestone is locally reviewable;
broader index parity remains part of A19.

The next library increments correct SSH command-selection precedence, make selected HTTPS CA bundles
exclusive while preserving the older additive-roots API, and preserve whitespace before
configuration continuations. Their focused evidence uses original fixtures and the installed Git
executable. These local library changes do not yet broaden jj's transport admission policy. Native
Linux/Windows execution and the full A19 replacement gate remain open. The sections below retain the
earlier integration evidence and its scope.

## Consumer Inventory and Design

The target manifests directly name `gix` in jj-lib and jj-cli and initially named `gix-ignore` in
jj-lib. The initial production source inventory found gix or gix-ignore use in 15 files: jj-lib's
Git backend, import and export layer, subprocess adapter, ignore matcher and workspace creation,
plus CLI URL, config, remote, clone, init, colocation, Gerrit and cleanup paths.
`lib/src/git_backend.rs` owns object storage, commit and tree codecs, copy inference, refs and GC.
`lib/src/git.rs` owns import/export, remote selection and command workflows.
`lib/src/git_subprocess.rs` invokes Git for fetch, push, remote discovery, branch pruning and
worktree operations. GC was a separate Git invocation in the backend. This is an inventory of the
target, not a declaration that every call has migrated.

The bounded integration order is to move byte-preserving ignore and storage operations, then refs
and import/export, followed by local and network transfer, worktree administration and the CLI's
exposed gix types. Each workflow must report structured girt errors and preserve jj's policies and
UI. A final subprocess and dependency audit is required after these paths move. The current slice
deliberately leaves the remaining gix and Git subprocess calls visible rather than hiding them
behind a fallback.

### R35-E1 — Ref Publication Log Policy

**Decision needed:** Map jj's committer overrides and Git's effective reflog settings into girt's
explicit append/preserve policy for general ref creation, movement and HEAD detachment. An
unconditional append can create logs where Git would not, particularly for tags or bare
repositories; preserving every log can discard expected history. **Safe current behavior:** Girt
handles deletion and no-log direct creation or movement under guarded policy; other writes stay on
gix. **Restart criteria:** Prove effective config and identity selection, existing-log behavior,
bare/nonbare defaults, and annotated-tag updates in both object formats, then validate external Git
reflog observations and jj's export conflicts.

The guarded creation and movement adapter checks `core.logAllRefUpdates=false`, the absence of an
existing log, file refs, no namespace or relevant shared/fsync overrides, and a valid Git committer.
Movement requires the raw stored target to be the exact old direct commit and publishes under a
conditional expected-value lock; symbolic refs and annotated tags retain gix. Lock contention falls
back to gix before publication. All 25 focused export cases and the combined 132-case jj-lib Git
integration suite and eight CLI import/export cases pass after the later remote rename change.

## Worktree and Transport Boundaries

Six production Git subprocess endpoint groups remain active. For worktrees, girt can register an
orphan checkout, repair its links and prune an exact retired registration. jj also supports adding a
worktree to a populated directory by moving a temporary gitfile. Its current Git invocation requests
relative links for portability. Girt change `ownmswpo` adds an explicit link style for one creation
or repair operation; the existing APIs still follow persistent `extensions.relativeWorktrees`. The
override changes the written links without changing shared configuration. The focused girt create
and repair suites pass 12 and nine cases, including Git reads of both override styles; all-target
warning-denying Clippy and docs.rs pass on macOS. This resolves the link policy prerequisite.
Pruning must target the registration jj just disconnected and prove retirement; a missing checkout
alone is insufficient. These contracts remain unintegrated. Girt creation and repair also require
the caller to exclude competing worktree administration or relocation; jj has not established that
exclusion for its ordinary workspace commands.

### R35-W1 — Worktree Retirement Proof

**Decision needed:** Define how jj proves that an exact Git worktree registration is retired while
other Git or jj processes may move or reuse it. Girt's `WorktreeRetirement::Confirmed` requires
excluding those noncooperating moves. jj's ordinary forget/remove path cannot establish that
condition. **Safe current behavior:** Keep the existing Git worktree prune path. An attempted girt
prune adapter passed all 51 CLI workspace cases, but was withdrawn because those tests cannot prove
the required exclusion. **Restart criteria:** Supply a safe protocol or revised API that refuses
ambiguous retirement, then test concurrent move/reuse and external Git observations.

The bounded worktree acceptance cases are: a moved checkout whose old backlink is stale; reuse of
the same registration name; an unrelated live registration with private HEAD, index, refs and logs;
an external administrator racing link repair; and a checkout whose `.git` link changes between
inspection and mutation. Each ambiguous case must refuse deletion or report exact partial effects.
Successful creation and repair must retain jj's per-operation relative links, leave repository
configuration unchanged, and remain readable by Git.

Girt has prepared fetch/push workflows for local and network transports. The bounded local fetch
path above maps one supported subset of named remotes, positive and negative refspecs, pruning and
remote-tag publication. The jj adapter also maps a bounded local push, including exact leases and
individual rejections. Depth, live progress, general reflog policy, network fetch, push options and
uncertain multi-ref outcomes remain across the other transport cases.

### R35-P1 — Native Local Push Semantics

Girt change `lknpuyuk` materializes Git's canonical empty tree for push preparation when source
storage omits it. jj change `wqzkoloz` pushes through girt for one absolute local URL with default
branch tracking, file refs, no receive hooks or reflogs, no push options or live progress, and no
inherited receive policy that girt would miss. It maps exact lease and receiver rejections into jj's
existing result categories and updates the local tracking ref after accepted branch pushes.
Unsupported receive policy and an already-current destination with a stale lease use Git before
native publication. Native uncertain outcomes are reported without retry. The native path succeeds
with a deliberately missing Git executable; jj's 20 push library tests and 47 CLI push tests pass.

**Remaining:** Inherited configuration, hooks, push options, nondefault tracking, multiple URLs,
reflogs and general transport stay on Git. Validate uncertain multi-ref publication and concurrent
local tracking updates before broadening the native path.

The bounded push acceptance cases are: inherited global/system/environment URL rewrites and protocol
policy; one versus several push URLs; sender hooks skipped while receiver hooks still run; push
options delivered or explicitly refused before sending; one stale lease alongside an accepted ref;
one receiver policy rejection alongside an accepted ref; and an interrupted multi-ref push whose
unacknowledged refs remain uncertain. Compare jj's CLI categories and remote refs after each case
before enabling the native path.

## Ignore Matching

Girt now exposes `Ignore::check_direct`, which tests the named path without checking excluded
ancestors. jj's snapshot traversal already checks each directory and skips an ignored subtree, so
using girt's whole-path query there would change established matching behavior. The adapter compiles
each `.gitignore` source as bytes, retains source precedence through jj's parent chain, and
propagates invalid-path or resource-limit errors as snapshot failures. The direct jj-lib dependency
on `gix-ignore` is removed; that crate remains transitively reachable through gix.

## B09 Additive Maintenance

An ordinary jj process still cannot prove `MaintenanceIsolation` against independent Git writers,
pinned old readers or alternate dependents. The Git backend therefore no longer launches `git gc`
and never calls girt's destructive maintenance API. It adds current jj index heads to no-GC refs
without deleting old refs, runs jj's existing extra-metadata cleanup, and asks girt to publish a
pack after a fresh retention scan. The policy includes those heads and jj's recent-object cutoff.
The CLI reports published pack and index byte counts followed by “reclamation deferred”, or a
specific deferred reason if a size bound prevents repacking. Git objects, old packs, loose objects,
reflogs and existing keep refs are not removed by this path. This is **not full GC equivalence**.

The adapter limits retained `refs/jj/keep/` names to 100,000, declines another repack when the
observed primary pack directory already exceeds 4 GiB, and uses girt's default per-run bounds of 512
MiB for input and pack output and 64 MiB for index output. One successful invocation can still add
up to 576 MiB after the precheck; other writers can grow storage independently. These are bounds on
jj's work, not a disk quota. Existing storage and old refs accumulate until a future safe
reclamation design is accepted. Girt's additive publication does not promise power-loss
directory-entry durability, and interruption can leave an unindexed pack. The CLI does not yet
provide a cancellation signal to this synchronous operation.

The follow-up jj change `vptpwqox` at `0e5c9943` uses girt's conditional transactions to create keep
refs during commit writes, imports and maintenance. It preserves existing values and reflogs; the
maintenance inventory is capped at 200,000 total refs and 64 MiB of ref data before the 100,000
keep-ref check. Exceeding an inventory bound defers repacking. The focused jj backend suite, five
CLI GC cases, full jj-lib unit suite (1,038 tests), full jj-cli runner (1,133 tests) and
warning-denying Clippy pass. Other Git refs remain on gix.
