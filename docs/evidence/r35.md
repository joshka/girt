# R35 Bounded Unix Integration Attempt

## Status and Target

### Current Local Milestone

The final target is a jj integration with no production Git executable, gix or libgit2 dependency,
including native worktree cleanup with conservative registration retention. Every remaining fallback
is temporary; scoped library acceptance and passing adapter tests do not close the A19 replacement
gate.

The earlier released-girt 0.1.5 milestone added bounded HTTP fetch and push with ordinary hosts, one
same-origin initial discovery redirect, sideband messages and push-option defaults. Later local work
delivers live HTTP fetch and push notices and separates index, reference and HTTP policy into
`git_index`, `git_refs`, `git_http` and `git_worktree` modules. These module boundaries organize the
remaining replacement work; they do not establish complete parity.

Native worktree creation and repair include first-use relative-link configuration promotion; symlink
cases retain fallback. The approved R35-W1 contract replaces Git pruning with identity-qualified
native detachment that preserves uncertain registrations and their private roots. Physical cleanup
requires a separate explicit operation; an absent checkout path is never retirement proof. The
conservative cleanup adapter is integrated locally, including fresh registration identities on
checkout-path reuse and explicit recovery locations after unsafe detachment. Broader index and
worktree lifecycle parity remain open. Girt now inventories private roots from valid retained
registrations even when a replacement checkout uses another registration. Invalid private metadata
still prevents a complete retention plan. Installed Git GC preserves retained HEAD, recent
HEAD-reflog and index roots in both object formats. Its omission of private-ref-only roots also
occurs in the untouched baseline; girt retains those roots conservatively.

The combined local girt prerequisites pass the full 3,983-test gate, Clippy, formatting and docs
checks. They include conditional existing-log updates, typed HTTP fetch validation progress, local
fetch and push preparation progress, retained-registration root discovery, grouped config editing,
and Git-compatible reftable timezone encoding. jj consumes the fetch and push progress for eligible
transfers; upload and installation can remain quiet, and preparation completion does not establish
push success. The integrated jj stack passes all 50 colocation cases and strict Clippy; workspace
cleanup passes all 56 cases.

Native SSH discovery, fetch and push are integrated for headless macOS processes whose first `ssh`
executable resolves to system OpenSSH. It preserves inherited environment and configuration, streams
bounded local diagnostics and remote progress, and never retries after launch. Transfers use a
60-second deadline. Caller-owned cancellation tracks worker completion independently of display
callbacks; real CLI INT, TERM and HUP tests stop the owned SSH group with the display blocked.
Cleanup timeout reports incomplete cleanup and does not promise a hard OS termination bound.
Interactive terminals, custom commands and other platforms remain outside this admission. Push
batches mixing already-current or stale updates with other changes, and deletion without an expected
old object ID, remain unsupported in this slice. General HTTPS trust remains open. Consumer fixtures
inject a disposable SSH executable below the production admission gate; they do not establish
interoperability with a real SSH host.

The combined consumer stack passes 18 SSH unit tests and strict library/CLI Clippy, including the
signal-test feature. The isolated transfer lanes also pass 79 existing fetch and 70 existing push
regressions. Porcelain object IDs now use girt, with ten parser tests preserving mixed object-format
widths, uppercase and null IDs, and existing error categories. The full jj suite has not been rerun
for this increment.

Eligible remote listing now consumes an immutable backend-owned girt config snapshot and validates
ordinary names and canonical URL forms without gix parsing. Eligible macOS config source paths are
selected directly; public gix trust and repository bootstrap remain. Unusual config and URL policies
retain fallback. Snapshot, private-worktree, continuation-whitespace and URL rendering cases pass
focused consumer tests.

Native standalone index reset and intent-to-add accept V4 input and select V2/V3 output from entry
flags. Addition-only no-op updates preserve entries, stat data and TREE while normalizing framing;
optional EOIE acceleration output is omitted. Other extensions and alternate-index policies retain
fallback. Both object formats pass the public writer and installed-Git comparisons.

Windows validation is blocked by the Git oracle's disposable-CA handling. A local fixture change
selects Git for Windows' OpenSSL backend explicitly, with certificate and hostname verification
enabled; its Windows result is not yet verified. Native Linux/Windows consumer execution, remaining
transport and lifecycle contracts, and the final subprocess and dependency audit remain open. The
sections below retain earlier integration evidence in its original scope.

### R35-E1 — Ref Publication Log Policy

**Decision needed:** Map jj's committer overrides and Git's effective reflog settings into girt's
explicit append/preserve policy for general ref creation, movement and HEAD detachment. An
unconditional append can create logs where Git would not, particularly for tags or bare
repositories; preserving every log can discard expected history. **Safe current behavior:** Girt
handles deletion and no-log direct creation or movement under guarded policy; other writes stay on
gix. **Restart criteria:** Prove effective config and identity selection, existing-log behavior,
bare/nonbare defaults, and annotated-tag updates in both object formats, then validate external Git
reflog observations and jj's export conflicts.

The guarded creation and movement adapter checks `core.logAllRefUpdates=false`, the absence of an
existing log, file refs, no namespace or relevant shared/fsync overrides, and a valid Git committer.
Movement requires the raw stored target to be the exact old direct commit and publishes under a
conditional expected-value lock; symbolic refs and annotated tags retain gix. Lock contention falls
back to gix before publication. All 25 focused export cases and the combined 132-case jj-lib Git
integration suite and eight CLI import/export cases pass after the later remote rename change.

## Worktree and Transport Boundaries

The earlier boundary inventory identified six production Git subprocess endpoint groups. For
worktrees, girt can register an orphan checkout, repair its links and prune an exact retired
registration under caller-supplied exclusion. These primitives do not yet provide jj's complete
ordinary worktree lifecycle. jj also supports adding a worktree to a populated directory by moving a
temporary gitfile. The Git fallback requests relative links for portability. Girt change `ownmswpo`
adds an explicit link style for one creation or repair operation; the existing APIs still follow
persistent `extensions.relativeWorktrees`. The override changes the written links without changing
shared configuration. The focused girt create and repair suites pass 12 and nine cases, including
Git reads of both override styles; all-target warning-denying Clippy and docs.rs pass on macOS. This
resolves the link policy prerequisite. Later local adapters cover bounded creation and repair with
relative-link configuration promotion. Native cleanup must identify the selected registration
without deleting unrelated or uncertain metadata. The approved consumer behavior preserves uncertain
registrations in Git's recognized worktree metadata tree, including private HEAD, refs, index and
logs. Replacements use fresh registration identities; checkout-path reuse must not reuse a possibly
live registration pathname.

### R35-W1 — Worktree Retirement Proof

**Approved behavior:** Replace the Git prune subprocess with native identity-qualified detachment
and explicit reporting of retained registration metadata. Preserve ambiguous registrations and
private roots; never infer retirement from a missing path, stale backlink or `.git` unlink. This is
an intentional difference from Git's automatic pruning, not a claim of physical-prune parity.

**Completion criteria:** Verify the intended repository and registration before detachment, refuse
ambiguous link replacement, preserve moved checkouts and unrelated roots, and support replacement
workspaces through collision-safe new registration identities. Report retained/deferred cleanup to
the user and verify the approved path with no Git executable. Complete Git/gix/libgit2 removal
remains the A19 goal; automatic deletion of uncertain metadata is not required.

**Explicit cleanup backlog:** Resume destructive retirement only when a caller can establish a real
exclusive-administration/lifetime contract through deletion. `WorktreeRetirement::Confirmed` records
that obligation but does not prove it. Git's worktree lock is not a writer-exclusion mechanism. Do
not move metadata outside Git's recognized roots or reuse registration paths as a substitute for
proof.

Acceptance cases cover moved checkouts, checkout-path and registration-name reuse, unrelated private
roots, concurrent link repair, and `.git` replacement between inspection and mutation. Ambiguous
cases retain data or report exact partial effects. Creation and repair retain relative links and
remain readable by Git.

Girt has prepared fetch/push workflows for local and network transports. The bounded local fetch
path above maps one supported subset of named remotes, positive and negative refspecs, pruning and
remote-tag publication. The jj adapter also maps a bounded local push, including exact leases and
individual rejections. Later local HTTP and live-notice work extends this baseline as recorded
above. Depth, broader reflog and transport policy, and uncertain multi-ref outcomes still require
consumer acceptance; bounded successes do not remove the remaining production fallbacks.

## Ignore Matching

Girt now exposes `Ignore::check_direct`, which tests the named path without checking excluded
ancestors. jj's snapshot traversal already checks each directory and skips an ignored subtree, so
using girt's whole-path query there would change established matching behavior. The adapter compiles
each `.gitignore` source as bytes, retains source precedence through jj's parent chain, and
propagates invalid-path or resource-limit errors as snapshot failures. The direct jj-lib dependency
on `gix-ignore` is removed; that crate remains transitively reachable through gix.

## B09 Additive Maintenance

An ordinary jj process still cannot prove `MaintenanceIsolation` against independent Git writers,
pinned old readers or alternate dependents. The Git backend therefore no longer launches `git gc`
and never calls girt's destructive maintenance API. It adds current jj index heads to no-GC refs
without deleting old refs, runs jj's existing extra-metadata cleanup, and asks girt to publish a
pack after a fresh retention scan. The policy includes those heads and jj's recent-object cutoff.
The CLI reports published pack and index byte counts followed by “reclamation deferred”, or a
specific deferred reason if a size bound prevents repacking. Git objects, old packs, loose objects,
reflogs and existing keep refs are not removed by this path. This is **not full GC equivalence**.

The adapter limits retained `refs/jj/keep/` names to 100,000, declines another repack when the
observed primary pack directory already exceeds 4 GiB, and uses girt's default per-run bounds of 512
MiB for input and pack output and 64 MiB for index output. One successful invocation can still add
up to 576 MiB after the precheck; other writers can grow storage independently. These are bounds on
jj's work, not a disk quota. Existing storage and old refs accumulate until a future safe
reclamation design is accepted. Girt's additive publication does not promise power-loss
directory-entry durability, and interruption can leave an unindexed pack. The CLI does not yet
provide a cancellation signal to this synchronous operation.

The follow-up jj change `vptpwqox` at `0e5c9943` uses girt's conditional transactions to create keep
refs during commit writes, imports and maintenance. It preserves existing values and reflogs; the
maintenance inventory is capped at 200,000 total refs and 64 MiB of ref data before the 100,000
keep-ref check. Exceeding an inventory bound defers repacking. The focused jj backend suite, five
CLI GC cases, full jj-lib unit suite (1,038 tests), full jj-cli runner (1,133 tests) and
warning-denying Clippy pass. Other Git refs remain on gix.
