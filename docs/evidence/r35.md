## Consumer Inventory and Design

The target manifests directly name `gix` in jj-lib and jj-cli and `gix-ignore` in jj-lib. The
production source inventory finds gix or gix-ignore use in 15 files: jj-lib's Git backend, import
and export layer, subprocess adapter, ignore matcher and workspace creation, plus CLI URL, config,
remote, clone, init, colocation, Gerrit and cleanup paths. `lib/src/git_backend.rs` owns object
storage, commit and tree codecs, copy inference, refs and GC. `lib/src/git.rs` owns import/export,
remote selection and command workflows. `lib/src/git_subprocess.rs` invokes Git for fetch, push,
remote discovery, branch pruning and worktree operations. GC was a separate Git invocation in the
backend. This is an inventory of the target, not a declaration that every call has migrated.

The bounded integration order is to move byte-preserving ignore and storage operations, then refs
and import/export, followed by local and network transfer, worktree administration and the CLI's
exposed gix types. Each workflow must report structured girt errors and preserve jj's policies and
UI. A final subprocess and dependency audit is required after these paths move. The current slice
deliberately leaves the remaining gix and Git subprocess calls visible rather than hiding them
behind a fallback.

## Ignore Matching

Girt now exposes `Ignore::check_direct`, which tests the named path without checking excluded
ancestors. jj's snapshot traversal already checks each directory and skips an ignored subtree, so
using girt's whole-path query there would change established matching behavior. The adapter compiles
each `.gitignore` source as bytes, retains source precedence through jj's parent chain, and
propagates invalid-path or resource-limit errors as snapshot failures. The direct jj-lib dependency
on `gix-ignore` is removed; that crate remains transitively reachable through gix.

## B09 Additive Maintenance

An ordinary jj process still cannot prove `MaintenanceIsolation` against independent Git writers,
pinned old readers or alternate dependents. The Git backend therefore no longer launches `git gc`
and never calls girt's destructive maintenance API. It adds current jj index heads to no-GC refs
without deleting old refs, runs jj's existing extra-metadata cleanup, and asks girt to publish a
pack after a fresh retention scan. The policy includes those heads and jj's recent-object cutoff.
The CLI reports published pack and index byte counts followed by “reclamation deferred”, or a
specific deferred reason if a size bound prevents repacking. Git objects, old packs, loose objects,
reflogs and existing keep refs are not removed by this path. This is **not full GC equivalence**.

The adapter limits retained `refs/jj/keep/` names to 100,000, declines another repack when the
observed primary pack directory already exceeds 4 GiB, and uses girt's default per-run bounds of 512
MiB for input and pack output and 64 MiB for index output. One successful invocation can still add
up to 576 MiB after the precheck; other writers can grow storage independently. These are bounds on
jj's work, not a disk quota. Existing storage and old refs accumulate until a future safe
reclamation design is accepted. Girt's additive publication does not promise power-loss
directory-entry durability, and interruption can leave an unindexed pack. The CLI does not yet
provide a cancellation signal to this synchronous operation.

The follow-up jj change `vptpwqox` at `0e5c9943` uses girt's conditional transactions to create keep
refs during commit writes, imports and maintenance. It preserves existing values and reflogs; the
maintenance inventory is capped at 200,000 total refs and 64 MiB of ref data before the 100,000
keep-ref check. Exceeding an inventory bound defers repacking. The focused jj backend suite, five
CLI GC cases, full jj-lib unit suite and warning-denying Clippy pass; the full CLI suite is in
progress. Other Git refs remain on gix.

## Evidence and Remaining Gates

The focused girt ignore suite passed 44 tests, all 25 doctests passed, and warning-denying
all-target Clippy and docs.rs passed on macOS. jj-lib's full unit suite passed 1,038 tests and the
jj-cli runner passed all 1,132 tests at `3d12d434`; warning-denying Clippy passed for both crates.
The added sparse-file limit case passed at `b5ba393a` without publishing another pack. Within those
suites, jj-lib's ignore suite passed 28 tests, the jj CLI ignore suite passed three, and the GC
argument, operation-log and new alternate-dependency cases passed. The GC test exercises both SHA-1
and SHA-256 and sets `git.executable-path` to a nonexistent path. Independent disposable Git checks
also read a blob from an alternate repository after jj GC, pass `git fsck --full`, and reopen the jj
commit in both formats. These prove the tested additive path, not concurrent deletion safety or
replacement of the rest of the Git stack. No native cross-platform matrix has run for this
integration tree.

The remaining A19 work includes copy inference migration, refs and import/export, fetch/push/clone
and worktree paths, Gerrit, config/URL boundaries, targeted A19 workflow suites on native platforms,
mixed-writer races, representative resource comparisons and a production subprocess/dependency
audit. Reassess transport protocol, progress and native receive exclusions against actual jj
destinations. B04's intermittent tracing and Windows split-index Git-oracle failures remain open;
B01, B02/B03, B05, B07 and B08 retain their documented restart criteria. Do not report final
replacement or universal compatibility from the current partial tests.
