## Validation Scope

The [workflow](../../.github/workflows/validation.yml) is the executable command inventory. Unix
runs `cargo +stable test --locked --all-features`, then independently executes core-only units and
`object_ids`, `sha256`, `commits`, `packs`, `index` and `references` without tracing. It also runs
HTTP-only `http`/`http_portable` and SSH-only `ssh` runtime suites. Windows executes all-feature and
core-only units, all-feature doctests, its explicit core-only portable integration selection and
HTTP-only `http_portable`.

Every runner separately executes `tracing` and `tracing,http` versions of the tracing suite, checks
core-only, HTTP-only, SSH-only and `tracing,ssh` libraries, and runs all-feature/all-target Clippy
with warnings rejected. SSH compilation on Windows does not expose or validate a Windows SSH
adapter. Unix private Rustdoc and Windows public Rustdoc reject warnings.

All runners execute `content_diff`, `index`, `write_pack`, `init_repository` and the `tracing`
example. Unix also executes local fetch/push, HTTP/SSH, reference transaction, status and checkout
examples. `index`, `write_pack`, `init_repository` and `reference_transaction` exercise SHA-256;
transport examples retain SHA-1 negotiation.

### Format, Failure and Concurrency Evidence

Named executed SHA-1/SHA-256 cases provide format evidence, rather than suite names or compilation:

- `object_ids` and `sha256` cover identity/hash vectors, codecs, loose stores, Git-generated
  layouts, traversal and foreign-format refusal. Unix additionally exercises packed checkout and
  HEAD-based status.
- `packs` compares real Git OFS/REF deltas for blobs, trees, commits and tags in both formats.
  `git_indexes_and_reads_internal_deltas` and empty/mixed export cases compare generated indexes and
  reconstructed bytes with Git. Corrupt loose precedence, absent pairs, snapshot bounds and retained
  reads after repacking remain exercised.
- `index` runs both-format stat/flag round trips, Git-compatible writes, conflict stages and byte
  paths, linked/separate layouts, foreign locks and unsupported-version/extension refusals. These
  byte-path fixtures do not claim Windows filesystem support for non-UTF-8 names or symlinks.
- Unix `references` exercises both-format reads, conditional updates, packed deletion, reflogs and
  concurrent writers. Units retain transaction partial-publication and index write/rename/lock
  failure cases. Windows uses Git-managed refs in portable fixtures; this is not evidence of a
  supported girt Windows ref backend.
- Existing HTTP/SSH suites retain their platform-specific deadline, cancellation, truncation,
  rejection and uncertain-outcome cases. Tracing verifies caller-owned subscribers, safe fields,
  failure classification and worker/async context under the selected feature combinations.

Fixtures are the original locally generated corpora described in [R01](r01.md), [R02](r02.md),
[R03](r03.md), [R04](r04.md) and [R05](r05.md). Git CLI observations in disposable repositories are
independent compatibility evidence. This refresh adds no upstream implementation or test material.
Finite tests do not establish universal Git parity or unbounded fault/race coverage.

## Windows Validation Fix and Public API Effects

[Initial run 36100702703](https://github.com/joshka/girt/actions/runs/36100702703), at
`b185c6febf7fe7825bb076e6de1833e54caf3ac2`, passed all three Unix jobs. Windows passed both tracing
configurations and portable HTTP, but Clippy rejected oversized result errors after identity
widening; subsequent normal test/example/doc steps were skipped.

The corrected revision boxes three existing public error fields:

- `fetch::FetchFinishError::source` is now `Box<FetchFinishFailure>`.
- `TreeCompareError::Read::source` is now `Box<ObjectReadError>`.
- `status::Error::Object::source` is now `Box<ObjectReadError>`.

Callers constructing these fields wrap the cause in `Box::new`; owned pattern matches dereference
the box. Borrowed inspection uses `as_ref()`. Error-source downcasts see the boxed concrete type;
the concrete causes, display messages and source chains remain available. Fetch partial-effect
reports and operation return types are unchanged. No new public module or operation is added.
Existing fetch/clone failure assertions were migrated, and corruption/cancellation cases also check
source-chain access. No warning suppression or platform gating was added.

Benchmarking is inapplicable to this CI refresh and cold error-allocation correction: no successful
processing path or throughput claim changes. No new benchmark numbers are asserted.

[Run 36104635035](https://github.com/joshka/girt/actions/runs/36104635035), at
`eda3dae2e0d4329c9ca789ee652cf7261f1aa5e4`, confirmed native Windows Clippy success but exposed four
existing pack-import fixture failures. Git for Windows rejected Rust's verbatim absolute paths
passed to `verify-pack` and `index-pack`. The final revision passes repository-relative paths to
those commands, preserving all four SHA-1/SHA-256 OFS/REF-delta cases and their assertions. This is
a fixture correction, with no production behavior or capability change. The failed run's
[logs](/Users/joshka/.codex/reports/girt-r06/second-run.log) remain available.

## Remaining Boundaries

Windows references/reflogs, composed fetch/clone publication, local/SSH process adapters, actual
status traversal and checkout materialization remain unsupported. Status/checkout portable cases
only establish cancellation precedence and explicit refusal. Windows HTTP remains bounded loopback
plaintext coverage; HTTPS/trust and the full Unix transport fault matrix remain unverified.

R11 owns portable refs; R12 owns broader index semantics; R14–R16 own broader pack/store acceptance,
bounded reads and refresh; R26/R29 own SHA-256 transport negotiation. R36 audits omitted portable
coverage separately from capability exclusions, with closure by C02. Completing this bounded R06
refresh does not complete A16's later platform gates or jj readiness.
