## Public Surface and Behavior

The `config` module separates parsing (`parse.rs`), explicit inputs/provenance (`sources.rs`),
resolution (`resolution.rs`), byte wildcard matching (`wildmatch.rs`) and shared scalar parsing
(`values.rs`). `Config::parse` remains pure; it now retains name spelling and physical entry lines
and accepts deprecated dotted subsections with ASCII case folding. `Config::entries` exposes ordered
`Entry` values, with optional `Origin` containing scope, location and nested include ancestry.

`Config::resolve(&ConfigInputs)` performs bounded read-only resolution of system/global/local/
worktree sources, supplied environment pairs and caller overrides. `ConfigFile`, `ConfigScope`,
`IncludeContext`, `ResolveLimits`, `SourceLocation`, `ResolveError` and `ResolveFailure` define
source policy, context, budgets and inspectable failures. `ConfigInputs::from_environment` accepts
OS-string lookup over an explicit snapshot; `Config::from_environment` decodes literal COUNT/KEY/
VALUE pairs. Neither reads nor changes process environment. File selectors follow HOME/XDG,
SYSTEM/GLOBAL and NOSYSTEM precedence. Scalar lookup returns the last value; repeated/empty/implicit
occurrences remain distinct.

Includes expand in occurrence order with relative paths and explicit home/user-home/prefix mappings.
Conditional includes cover gitdir, gitdir/i, onbranch and hasconfig remote URLs, including later
layers. Hasconfig targets and their descendants cannot declare remote URLs, even when unmatched.
Unknown conditions do not match; empty include paths are inert. Optional missing sources are
ignored, required missing sources and all malformed/unreadable sources fail with context. Canonical
ancestor identities detect cycles. Depth, loaded/expanded bytes, visited entries and wildcard work
have explicit budgets. Old snapshots remain stable after external changes; refresh requires another
resolve/open. Concurrent multi-source coherence requires caller coordination.

`Repository::open_with_config` supplies common/private sources and HEAD/Git-directory context;
`Repository::open` resolves repository-local sources without ambient policy. `OpenError::Resolve`
retains resolver failures. Object format is bootstrapped from direct common config; includes,
worktree format entries and overrides cannot reinterpret it. Direct enabled worktree core settings
participate in layout bootstrap. `Repository::config` feeds resolved values to existing
`Remote::find`, including inherited URL resets. No compatibility wrappers or dependencies were
added. The [configuration contract](../configuration.md) and `examples/config.rs` teach usage.

## Original Observations and Acceptance

The specification input was the [Git configuration manual](https://git-scm.com/docs/git-config),
accessed 2026-09-25. All fixtures are original and constructed in disposable directories by
`tests/config_resolution.rs`; Git 2.55.0 is an executable oracle. No upstream implementation,
upstream tests or copyright-audit comparisons were used.

Forty macOS public-API cases cover precedence, XDG/home and file-selector overrides, literal runtime
pairs and accepted count spellings, URL reset consumption, nested relative includes and source
lines, branch/gitdir/case-folded/relative/home/unknown conditions, forward hasconfig lookup and
forbidden descendants, both repository formats, linked private Git directories, worktree scope,
format/layout bootstrap isolation, missing/empty/malformed sources, cycles, depth/byte/entry/glob
budgets, refresh, no writes and unchanged process environment. Unix symlink-alias matching is
tested; an additional arbitrary-byte filename case is Linux-only. Byte values, names and subsection
case are exercised portably. Conditions and precedence are compared to Git output, not only expected
library values.

Focused local tests additionally cover glob rules, environment failures, runtime-relative include
errors, repeated expansion amplification, explicit user/prefix expansion and missing expansion
context. Two tracing cases verify categorical cycle failure, parent hierarchy, redaction, span
closure and filtered-child isolation. Disabled tracing uses the same resolution suite.

Mutation/race fault injection is inapplicable to this read-only operation. Snapshots explicitly do
not promise an atomic multi-file generation. No cancellation or background worker API is introduced.
Bounds and structured read failures establish the synchronous operation's failure contract.

## Validation

On macOS arm64, Rust/Cargo 1.98.1 and Git 2.55.0:

- `just fmt` and `just check` pass: 1,503 unit tests, 883 integration cases, 20 doctests,
  all-feature/all-target Clippy and docs.rs with warnings denied.
- `cargo test --no-default-features --test config_resolution` passes all 40 local cases.
- `cargo run --example config` passes, including resolved remote lookup and scope/line assertions.
- `RUSTDOCFLAGS='-D warnings' cargo doc --no-deps --document-private-items` passes. Generated HTML
  contains the config type navigation and resolve/environment/provenance methods.
- Markdown lint passes at 100 columns, with the repository's documented table-width exception.
- Core libraries and `config_resolution` test targets cross-compile for Linux GNU and Windows GNU.
  The test-target checks use `CRATE_CC_NO_DEFAULTS=1` and explicit Zig C compiler targets; the
  initial Windows attempt identified the unavailable MinGW compiler and was corrected to Zig.
  Cross-compilation is not native runtime evidence.

The [source manifest](r08-source.sha256) fingerprints the implementation, integration fixtures,
example, benchmark, Cargo inputs and CI selection. Verify with
`shasum -a 256 -c docs/evidence/r08-source.sha256`. The final check log is retained in
[r08-check.log](r08-check.log); benchmark output is [r08-bench.log](r08-bench.log).

The existing repository Criterion harness now measures warm-cache resolution of 1,000 remotes and an
eleven-file, ten-include-edge chain. With 20 samples, one-second warmup and two-second measurement,
95% intervals were 1.6371–1.6506 ms and 387.78–393.68 µs respectively. Fixture creation is outside
the measurement. These are local observations, not thresholds, cold-storage claims or a proven
speedup.
